# Глава 0. Перед началом

Эта глава подготовит рабочее место и объяснит, как проходить учебник без
преподавателя. Здесь почти нет нового синтаксиса C++, но пропускать главу не
стоит: воспроизводимая сборка и правильный учебный ритм сэкономят много
времени позже.

## Что понадобится

Тебе нужны:

- компилятор с поддержкой C++20;
- CMake;
- текстовый редактор или IDE;
- терминал;
- отдельный каталог для учебных программ.

Подойдёт любой распространённый компилятор C++ с поддержкой C++20. IDE не
заменяет компилятор: она лишь помогает запускать его, читать код и работать с
отладчиком.

Проверь инструменты в терминале:

```bash
c++ --version
cmake --version
```

Названия команд могут отличаться на конкретной системе. Если первая команда
не найдена, найди в своей IDE выбранный toolchain и проверь, какой компилятор
она использует. Не продолжай, пока не сможешь собрать простейший проект из
терминала или через явно настроенный CMake-профиль IDE.

## Создай отдельное учебное рабочее место

Не выполняй упражнения внутри большой рабочей программы. Создай отдельный
каталог, например:

```text
cpp-study/
├── chapter-01/
├── chapter-02/
├── exercises/
└── signal-lab/
```

Так ты сможешь экспериментировать, намеренно ломать код и удалять сборочные
каталоги, не боясь повредить настоящий проект.

## Минимальный проект для проверки среды

Создай каталог `environment-check` с двумя файлами.

`main.cpp`:

```cpp
#include <iostream>

int main()
{
    std::cout << "C++20 окружение работает\n";
    return 0;
}
```

`CMakeLists.txt`:

```cmake
cmake_minimum_required(VERSION 3.20)
project(EnvironmentCheck LANGUAGES CXX)

add_executable(environment_check main.cpp)
target_compile_features(environment_check PRIVATE cxx_std_20)
set_target_properties(environment_check PROPERTIES CXX_EXTENSIONS OFF)
```

Сконфигурируй и собери проект:

```bash
cmake -S . -B build
cmake --build build
```

После сборки запусти получившуюся программу. Точное расположение executable
зависит от генератора и операционной системы. В одноконфигурационной сборке
он часто находится прямо в `build`, а в многоконфигурационной — в подкаталоге
вроде `build/Debug`.

Если проект собрался только по кнопке IDE, повтори сборку командами. Тебе не
нужно отказываться от IDE — важно лишь понимать, что она делает.

## Твой рабочий цикл

Для каждого упражнения используй один и тот же цикл:

1. Сформулируй ожидаемое поведение.
2. Запиши два обычных и один граничный пример входа.
3. Напиши минимальный код.
4. Собери программу.
5. Прочитай **первую осмысленную** ошибку компилятора.
6. Запусти программу.
7. Сравни фактический результат с прогнозом.
8. Измени пример и проверь, сохранилось ли понимание.
9. Запиши найденную ошибку и её причину в журнал.

Последний пункт очень полезен. Формат журнала может быть простым:

```text
Симптом: программа падала на пустом векторе.
Причина: код обращался к values[0] без проверки empty().
Как обнаружил: тест с пустым входом и debugger.
Как предотвратить: зафиксировать контракт до реализации.
```

Через несколько недель такой журнал станет твоим персональным справочником.

## Как работать с примерами

Не копируй большой фрагмент и не нажимай сразу Run. Лучше:

1. Набери пример вручную.
2. После каждой функции остановись и объясни её назначение.
3. До запуска предскажи вывод.
4. Измени одно значение.
5. Добавь один граничный случай.
6. Намеренно внеси маленькую ошибку и прочитай диагностику.

Если пример работает, но ты не можешь объяснить, почему ссылка безопасна или
кто владеет объектом, пример ещё не усвоен.

## Как пользоваться подсказками и решениями

В главах подсказки скрыты в раскрывающихся блоках. Используй их по одной:

1. сначала сделай самостоятельную попытку минимум 20–30 минут;
2. открой первую подсказку;
3. снова попробуй решить задачу;
4. только затем открывай следующую;
5. выбранное готовое решение смотри после собственной работающей или подробно
   разобранной неудачной версии.

После чтения решения закрой его и напиши задачу ещё раз на следующий день.
Иначе легко перепутать узнавание кода с умением его создать.

## Входная самодиагностика

Ответь без поиска:

1. Чем условие отличается от цикла?
2. Зачем функции параметры и возвращаемое значение?
3. Что должно произойти при попытке найти максимум пустого массива?
4. Что такое индекс элемента?
5. Почему результат вычисления с вещественными числами может немного
   отличаться от математически точного?

Не страшно, если ответы неполные. Эта диагностика нужна, чтобы увидеть
исходную точку. Запиши ответы и вернись к ним после пятой главы.

## План времени

Для одной обычной главы закладывай:

- 60–90 минут на первое чтение и примеры;
- 2–4 часа на упражнения;
- 30 минут на повторение на следующий день;
- дополнительное время на этап `SignalLab`.

Не пытайся «пройти главу» только чтением. В программировании понимание
проверяется изменением и запуском кода.

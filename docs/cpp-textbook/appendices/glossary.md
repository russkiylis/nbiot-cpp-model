# Словарь терминов

Определения здесь намеренно практические. Они помогают читать учебник, но не
заменяют формальные формулировки стандарта C++.

## A–C

### API

Публичный способ пользоваться компонентом: доступные функции, классы, типы и
их договорённое поведение.

### CMake

Инструмент, который по описанию целей проекта создаёт файлы для конкретной
системы сборки. CMake не является компилятором.

### Concept

Именованное ограничение для параметра шаблона. Помогает выразить, какие типы
допустимы, и получить более понятную диагностику.

### `const`

Обещание не изменять значение через конкретный интерфейс. `const` помогает
компилятору проверять намерение программы.

## D–I

### Debug-сборка

Конфигурация, удобная для поиска ошибок: обычно с отладочной информацией и без
агрессивных оптимизаций.

### Destructor — деструктор

Специальная функция, которая выполняется при уничтожении объекта. RAII-типы
освобождают принадлежащий им ресурс в деструкторе.

### Dynamic polymorphism — динамический полиморфизм

Выбор реализации виртуальной функции по реальному типу объекта во время
выполнения программы.

### Executable

Файл готовой программы, который можно запустить после успешной сборки.

### Invariant — инвариант

Условие, которое должно быть истинным после создания объекта и после каждого
успешного публичного вызова.

### Iterator — итератор

Объект, представляющий позицию в последовательности. Многие алгоритмы STL
работают с парами итераторов, задающими диапазон.

## L–O

### Lambda — лямбда

Небольшой объект-функция, объявленный прямо в месте использования. Часто
передаётся алгоритму как условие или операция.

### Lifetime — время жизни

Промежуток выполнения программы, в течение которого объект существует и к
нему разрешено обращаться.

### Linker — линкер

Инструмент, который связывает скомпилированные объектные файлы и библиотеки в
готовую программу.

### Move — перемещение

Операция, которая позволяет новому объекту забрать внутренние ресурсы старого
вместо дорогого копирования. Перемещённый объект остаётся корректным, но его
конкретное содержимое часто не следует предполагать.

### Object slicing

Потеря производной части объекта при копировании производного объекта в
значение базового типа.

### ODR — One Definition Rule

Набор правил о том, сколько определений сущности может существовать в
программе. На начальном уровне важно не помещать обычные определения
нетиповых функций в заголовок без подходящей причины.

### Ownership — владение

Ответственность за время жизни ресурса или объекта. Владелец определяет, когда
объект уничтожается.

## P–R

### Pointer — указатель

Значение, которое хранит адрес объекта либо `nullptr`. Сам по себе сырой
указатель не сообщает, владеет ли он объектом.

### Postcondition — постусловие

Обещание о состоянии результата или объекта после успешного выполнения
операции.

### Precondition — предусловие

Требование, которое вызывающий код обязан выполнить перед вызовом операции.

### RAII

Связывание ресурса со временем жизни объекта. Ресурс получается при создании
объекта и освобождается автоматически при его уничтожении.

### Reference — ссылка

Другое имя уже существующего объекта. Ссылка не владеет объектом и не
продлевает его время жизни в обычных учебных сценариях.

### Release-сборка

Конфигурация с оптимизациями, предназначенная для обычного запуска и
измерения производительности.

### Resource — ресурс

Не только память. Ресурсом может быть открытый файл, блокировка, сетевое
соединение, дескриптор устройства или другой объект, требующий освобождения.

## S–U

### Sanitizer

Инструментальная проверка, добавляемая компилятором. Помогает обнаруживать
выходы за границы, использование уничтоженной памяти и некоторые виды
неопределённого поведения.

### Scope — область видимости

Участок исходного кода, в котором имя доступно. Область видимости и время
жизни связаны, но не являются одним и тем же понятием.

### Smart pointer — умный указатель

RAII-объект, управляющий временем жизни динамически созданного объекта.
`unique_ptr` выражает одного владельца; `shared_ptr` — совместное управление
временем жизни.

### STL

В учебнике этим сокращением называется стандартная библиотека контейнеров,
итераторов и алгоритмов C++.

### Template — шаблон

Описание функции или типа, из которого компилятор создаёт конкретные версии
для выбранных параметров.

### Translation unit — единица трансляции

Результат обработки одного `.cpp` вместе со всеми включёнными заголовками.
Каждая единица трансляции компилируется отдельно.

### Undefined behavior — неопределённое поведение

Ситуация, для которой язык не задаёт допустимый результат. Пример — обращение
за границы массива. Программа может упасть, случайно сработать или проявить
ошибку позже.

## V–Z

### Value semantics — семантика значений

Модель, при которой объект ведёт себя как самостоятельное значение: его можно
копировать, перемещать, возвращать из функции и хранить в контейнере.

### Virtual function — виртуальная функция

Функция базового класса, для которой реализация может выбираться по реальному
типу объекта во время выполнения.

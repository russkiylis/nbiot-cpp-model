# Глава 9. Время жизни, ссылки, указатели и RAII

## Зачем нужна эта тема

Большинство особенно неприятных ошибок C++ связано не со сложной математикой, а с одним вопросом:

> Существует ли объект в тот момент, когда программа пытается его использовать?

В MATLAB управление памятью в основном скрыто средой выполнения. Ты создаёшь массив, присваиваешь его переменной, а освобождение происходит автоматически. В C++ стандартные типы тоже освобождают ресурсы автоматически, но язык позволяет создавать ссылки, указатели и представления на другие объекты. Они не продлевают время жизни исходных данных.

Поэтому нужно научиться различать:

- сам объект;
- владельца объекта;
- невладеющую ссылку или указатель;
- область видимости имени;
- фактическое время жизни значения.

Современный стиль C++ строится вокруг RAII: ресурс принадлежит объекту и освобождается его деструктором. В обычном прикладном коде ручные `new` и `delete` почти никогда не нужны.

## Результаты обучения

После этой главы ты сможешь:

- объяснить разницу между областью видимости и временем жизни;
- предсказать порядок уничтожения локальных объектов;
- понимать операции взятия адреса `&` и разыменования `*`;
- безопасно использовать `nullptr`;
- выбирать между значением, ссылкой, указателем и `std::span`;
- отличать владение от наблюдения;
- распознавать висячие ссылки, указатели и представления;
- объяснить, почему изменение `std::vector` может инвалидировать указатель на элемент;
- понимать принцип RAII и детерминированное освобождение ресурсов;
- применять Rule of Zero и стандартные владеющие типы;
- читать код с `new/delete` как демонстрацию риска, не используя его как основной стиль.

## 1. Объект, имя и область видимости

Рассмотрим блок:

```cpp
{
    int count = 5;
    // Здесь имя count доступно, а объект существует.
}
// Здесь имя count недоступно, а объект уже уничтожен.
```

**Область видимости** отвечает на вопрос: где в исходном коде доступно имя?

**Время жизни** отвечает на вопрос: в какой период выполнения программы существует сам объект?

Для обычной локальной переменной эти границы тесно связаны, но это не одно и то же понятие. Указатель может быть объявлен в более широкой области и продолжать хранить старый адрес после уничтожения объекта. Адрес останется числом, но объекта по этому адресу больше нет.

## 2. Автоматическое время хранения

Локальный объект без `static`, созданный обычным объявлением, имеет автоматическое время хранения:

```cpp
void process() {
    std::vector<double> values{1.0, 2.0, 3.0};
    // values существует до выхода из process
}
```

Объект создаётся при прохождении объявления и уничтожается при выходе из блока. Выход может произойти:

- обычным достижением закрывающей скобки;
- через `return`;
- из-за исключения.

Во всех случаях полностью созданные локальные объекты уничтожаются автоматически.

### Обратный порядок

Локальные объекты одного блока уничтожаются в порядке, обратном созданию:

```text
созданы:      first, second, third
уничтожены:   third, second, first
```

Это позволяет одному объекту безопасно использовать ранее созданный объект во время своей жизни.

## 3. Другие варианты времени хранения

Для общего понимания достаточно знать ещё два случая.

### Статическое время хранения

Глобальные переменные и локальные переменные с `static` обычно существуют до завершения программы. Изменяемое глобальное состояние затрудняет тестирование и понимание зависимостей, поэтому не используй его без веской причины.

### Динамическое время хранения

Объект может быть создан в динамической памяти. Исторический низкоуровневый интерфейс использует `new` и `delete`, но в современном C++ владельцем динамического объекта должен быть RAII-тип, прежде всего `std::unique_ptr` или стандартный контейнер.

Термины «стек» и «куча» часто употребляют как упрощение. Для рассуждения о корректности полезнее говорить «автоматическое» и «динамическое» время хранения: именно эти понятия определены моделью языка.

## 4. Адрес и указатель

У каждого существующего объекта есть адрес. Оператор `&` получает его:

```cpp
int value = 42;
int* pointer = &value;
```

Тип `int*` означает «указатель на `int`». Указатель хранит адрес, но сам по себе не говорит, кто владеет объектом и кто отвечает за его уничтожение.

Оператор `*` разыменовывает корректный указатель:

```cpp
std::cout << *pointer; // 42
*pointer = 100;        // меняет value
```

После присваивания `value` равно `100`, потому что запись прошла через адрес того же объекта.

### Нулевой указатель

Указатель может обозначать отсутствие объекта:

```cpp
int* pointer = nullptr;
```

Разыменовывать `nullptr` нельзя. До `*pointer` нужно доказать, что указатель не нулевой:

```cpp
if (pointer != nullptr) {
    std::cout << *pointer;
}
```

В условии часто пишут короче `if (pointer)`, но на первых этапах явное сравнение может читаться понятнее.

Не используй старые варианты `0` или `NULL` для нулевого указателя. `nullptr` имеет специальный указательный тип и избегает неоднозначности перегрузок.

## 5. Указатель не равен владельцу

Один и тот же синтаксический тип `T*` может использоваться по-разному:

- наблюдать существующий объект;
- обозначать необязательный объект;
- указывать на элемент массива;
- представлять низкоуровневый ресурс старого API;
- в старом коде — владеть результатом `new`.

Поэтому сырой указатель сам не выражает владение. В современном коде полезно придерживаться соглашения:

```text
T* и const T*      — обычно невладеющие наблюдатели;
T& и const T&      — невладеющие обязательные связи;
std::span          — невладеющий диапазон;
std::vector        — владелец последовательности;
std::unique_ptr    — единственный владелец динамического объекта.
```

При ревью любого указателя спрашивай:

1. На какой объект он указывает?
2. Кто владеет этим объектом?
3. Может ли объект исчезнуть раньше указателя?
4. Может ли операция с владельцем переместить объект?
5. Допустим ли `nullptr`?

## 6. Ссылка

Ссылка — другое имя существующего объекта:

```cpp
int value = 10;
int& reference = value;
reference = 25;
```

После присваивания `value` равно `25`.

Главные свойства обычной ссылки:

- должна быть привязана при создании;
- не имеет нормального «пустого» состояния;
- не переназначается на другой объект;
- не владеет объектом;
- должна использоваться только пока объект существует.

`const`-ссылка позволяет читать, но не менять:

```cpp
void print(const std::string& text);
```

Для обязательного аргумента без копирования обычно подходит ссылка. Для необязательной связи часто используют указатель или специальный тип вроде `std::optional` — в зависимости от того, нужно ли хранить значение или только наблюдать объект.

## 7. Значение, ссылка, указатель или `span`

### Передача по значению

```cpp
void process(std::vector<double> values);
```

Функция получает собственный объект. Это уместно, если ей нужна копия или она забирает владение переданным значением.

### Передача по `const&`

```cpp
void print(const std::vector<double>& values);
```

Функция обязательно получает существующий вектор, не копирует и не изменяет его.

### Передача по `&`

```cpp
void normalize(std::vector<double>& values);
```

Функция обязательно получает существующий вектор и может его изменить. Такое изменение должно быть очевидно из имени и контракта.

### Передача по указателю

```cpp
void printIfPresent(const Measurement* measurement);
```

Указатель полезен, если отсутствие объекта через `nullptr` является допустимой частью контракта.

### Передача по `std::span`

```cpp
double mean(std::span<const double> values);
```

`span` представляет непрерывный диапазон, не владеет элементами и не копирует их. Он может ссылаться, например, на `std::vector` или `std::array`.

Срок жизни данных должен быть дольше всех операций со `span`.

## 8. `const` и указатели

Положение `const` меняет смысл:

```cpp
const int* pointerToConst = &value;
```

Через этот указатель нельзя изменить `value`, но сам указатель можно направить на другой `int`.

```cpp
int* const constPointer = &value;
```

Сам указатель нельзя переназначить, но через него можно изменить `value`.

```cpp
const int* const constPointerToConst = &value;
```

Нельзя ни переназначить указатель, ни изменить объект через него.

На практике чаще всего встречается `const T*`: невладеющий указатель только для чтения.

## 9. Полностью компилируемый пример: безопасный невладеющий указатель

Функция ищет первый элемент выше порога и возвращает указатель на него. `nullptr` означает, что подходящего элемента нет.

```cpp
#include <iostream>
#include <span>
#include <vector>

double* findFirstAbove(std::span<double> values, double threshold) {
    for (double& value : values) {
        if (value > threshold) {
            return &value;
        }
    }
    return nullptr;
}

int main() {
    std::vector<double> samples{0.5, 1.2, 3.8, 2.1};

    double* found = findFirstAbove(samples, 2.0);
    if (found != nullptr) {
        std::cout << "Найдено: " << *found << '\n';
        *found = 4.0;
    }

    std::cout << "Вектор:";
    for (double sample : samples) {
        std::cout << ' ' << sample;
    }
    std::cout << '\n';
}
```

Разбор владения:

1. `samples` владеет элементами.
2. `span` внутри функции временно наблюдает элементы `samples`.
3. `found` тоже не владеет элементом. Он указывает внутрь `samples`.
4. Указатель корректен, пока соответствующий элемент существует по тому же адресу.
5. Изменение через `*found` меняет элемент вектора.

После получения `found` нельзя бездумно делать `samples.push_back(...)`: перевыделение памяти может переместить все элементы и сделать указатель висячим.

Если менять найденный элемент не нужно, функция должна возвращать `const double*` и принимать `std::span<const double>`.

## 10. Висячая ссылка или указатель

Висячий указатель хранит адрес объекта, время жизни которого уже закончилось.

Антипример:

```cpp
const int* brokenPointer() {
    int localValue = 42;
    return &localValue;
}
```

После выхода из `brokenPointer` объект `localValue` уничтожен. Использование возвращённого адреса — неопределённое поведение.

Программа может:

- случайно напечатать `42`;
- напечатать мусор;
- аварийно завершиться;
- вести себя по-разному в Debug и Release;
- сломаться после совершенно несвязанного изменения кода.

Именно поэтому «у меня один раз сработало» не доказывает корректность работы со временем жизни.

### Временные объекты

Опасность возникает и без явного локального указателя. Например, `std::string_view` или `std::span`, сохранённые на данные временной строки или временного вектора, переживут владельца.

Перед возвратом ссылки, указателя, `span` или `string_view` всегда устанавливай, какой объект владеет данными и насколько долго он живёт.

## 11. Инвалидирование при изменении контейнера

Даже если владелец ещё существует, адрес элемента может измениться.

`std::vector` хранит элементы в непрерывной памяти. Когда места не хватает, он выделяет новый блок и перемещает туда элементы. После такого перевыделения старые указатели, ссылки, итераторы и `span` на элементы становятся недействительными.

Опасный порядок:

```text
1. получить указатель на values[0];
2. выполнить push_back;
3. использовать старый указатель.
```

`reserve` может заранее уменьшить вероятность перевыделений, но это не универсальное решение владения. Надёжнее не хранить адрес элемента через операции, меняющие структуру контейнера, если такой контракт не нужен.

## 12. Деструктор

Деструктор вызывается при завершении времени жизни объекта. Его имя начинается с `~`:

```cpp
class Example {
public:
    ~Example() {
        // освобождение принадлежащего ресурса
    }
};
```

В большинстве твоих классов собственный деструктор писать не нужно. Поля `std::vector`, `std::string`, файловые потоки и умные указатели сами корректно освобождают свои ресурсы.

Это называется **Rule of Zero**: проектируй класс из готовых RAII-компонентов так, чтобы не писать вручную ни деструктор, ни операции копирования, ни операции перемещения.

## 13. RAII

RAII расшифровывается как Resource Acquisition Is Initialization: получение ресурса связывается с инициализацией объекта, освобождение — с его уничтожением.

Ресурсом может быть:

- динамическая память;
- открытый файл;
- сетевое соединение;
- блокировка мьютекса;
- системный дескриптор;
- временно изменённое состояние;
- измеряемый временной интервал.

Схема RAII:

```text
конструктор или фабрика получает ресурс;
объект становится владельцем;
методы используют ресурс;
деструктор освобождает ресурс;
выход по return или исключению тоже вызывает деструктор.
```

Стандартные типы уже реализуют эту схему:

- `std::vector` владеет динамическим массивом;
- `std::string` владеет строковыми данными;
- `std::ifstream` и `std::ofstream` владеют открытым файлом;
- `std::unique_ptr` владеет динамическим объектом;
- `std::lock_guard` владеет блокировкой на время области.

## 14. Полностью компилируемый пример: файл как RAII-ресурс

Программа сначала создаёт файл, затем читает его. Явный `close()` не нужен: файловые объекты закрывают ресурс при выходе из области.

```cpp
#include <cstddef>
#include <fstream>
#include <iostream>
#include <stdexcept>
#include <string>

int main() {
    const std::string fileName = "measurements.txt";

    {
        std::ofstream output{fileName};
        if (!output) {
            throw std::runtime_error("Не удалось открыть файл для записи");
        }

        output << 1.5 << '\n'
               << 2.0 << '\n'
               << 4.0 << '\n';
    } // output уничтожен, файл закрыт и данные сброшены

    std::ifstream input{fileName};
    if (!input) {
        throw std::runtime_error("Не удалось открыть файл для чтения");
    }

    double sum = 0.0;
    std::size_t count = 0;
    double value = 0.0;

    while (input >> value) {
        sum += value;
        ++count;
    }

    if (count == 0) {
        std::cout << "Файл не содержит чисел\n";
        return 0;
    }

    std::cout << "Среднее: "
              << sum / static_cast<double>(count)
              << '\n';
}
```

Разбор:

1. Первый блок ограничивает жизнь `output`.
2. При закрывающей скобке вызывается деструктор потока.
3. После этого файл можно безопасно открыть для чтения.
4. Если между открытием и концом блока возникло исключение, деструктор всё равно был бы вызван.
5. Файл `measurements.txt` остаётся на диске: RAII закрывает файловый дескриптор, но не означает автоматическое удаление самого файла.

## 15. Почему ручные `new` и `delete` опасны

Ниже — демонстрация старого ручного управления, а не рекомендуемый образец:

```cpp
double* values = new double[1000];
performOperationThatMayThrow(values);
delete[] values;
```

Если вызываемая операция выбросит исключение, строка `delete[]` не выполнится и память утечёт. Есть и другие риски:

- забыть `delete`;
- вызвать `delete` дважды;
- перепутать `delete` и `delete[]`;
- продолжить использовать адрес после освобождения;
- потерять единственный указатель на ресурс;
- неправильно реализовать копирование владельца.

Современная версия для массива значений:

```cpp
std::vector<double> values(1000);
performOperationThatMayThrow(values);
```

`std::vector` сам освободит память при любом выходе из области. Для одного динамического объекта используется `std::unique_ptr`, который подробно рассматривается дальше.

Не упражняйся в написании владельцев через сырой `new/delete`, пока задача не относится к разработке низкоуровневой библиотеки. Сначала научись выражать владение стандартными типами.

## 16. RAII и исключения

RAII особенно важен из-за нескольких путей выхода. Представь функцию, которая открыла два файла, выделила буфер и затем обнаружила ошибку. При ручном освобождении нужно правильно очистить всё на каждом пути.

Если каждый ресурс принадлежит локальному RAII-объекту, раскрутка стека при исключении автоматически уничтожит уже созданные объекты в обратном порядке. Код обработки ошибки не должен вручную помнить каждый ресурс.

Деструктор обычно не должен выбрасывать исключение: он может выполняться во время обработки уже существующего исключения. Освобождение ресурса проектируют так, чтобы оно было безопасным.

## 17. Связь с MATLAB

MATLAB скрывает большую часть управления памятью массивов. Копирование может оптимизироваться механизмом copy-on-write, а объекты handle-классов имеют ссылочную семантику.

В C++:

- локальный объект уничтожается детерминированно при выходе из области;
- обычное значение имеет явного владельца — переменную или содержащий объект;
- ссылка и указатель не продлевают жизнь владельца;
- `std::vector` сам владеет своим буфером;
- два обычных вектора после копирования являются независимыми значениями;
- RAII применяется не только к памяти, но и к файлам, блокировкам и другим ресурсам.

При работе с файлами в MATLAB можно открыть дескриптор и закрыть его вручную, а для гарантированной очистки применять специальный объект очистки. В C++ такой принцип встроен в повседневный стиль: файловый поток сам закрывается деструктором.

Самое полезное новое правило мышления:

> Когда видишь ссылку, указатель, `span` или `string_view`, сначала ищи владельца данных и сравнивай сроки жизни.

## 18. Типичные ошибки

### Возврат адреса локальной переменной

Локальный объект исчезает при выходе из функции. Возвращай значение либо указывай на объект, чей владелец гарантированно живёт дольше.

### Разыменование `nullptr`

Если указатель допускает отсутствие объекта, проверка является частью его контракта.

### Неинициализированный указатель

`int* pointer;` хранит неопределённое значение. Если объекта пока нет, инициализируй `nullptr`.

### Предположение, что указатель владеет объектом

Сам тип `T*` этого не сообщает. Найди реального владельца.

### Хранение указателя на элемент изменяемого вектора

`push_back`, `insert`, `erase`, `resize` и другие операции могут сделать адрес недействительным.

### Возврат `span` на локальный вектор

После завершения функции вектор уничтожен, а `span` остаётся висячим.

### Ручной `new/delete` для обычной коллекции

Используй `std::vector`, `std::string` или другой контейнер.

### Явный `close()` как единственная защита

До него может произойти ранний `return` или исключение. Пусть поток закроется деструктором; явный `close()` нужен только когда закрыть ресурс требуется раньше конца области и результат закрытия важен логике.

### Собственный пустой деструктор

Не добавляй деструктор «на всякий случай». Он может повлиять на автоматическое перемещение класса и создаёт ложное ощущение особого управления ресурсами.

### Слишком долгая жизнь объекта

RAII работает лучше, когда область владения минимальна. Не держи файл открытым всю программу, если он нужен только одной короткой операции.

## 19. Упражнения

### Уровень 1. Адреса и сроки жизни

1. Создай `int`, ссылку и указатель на него. Измени значение через ссылку и через указатель, затем объясни результат.
2. Напиши функцию `findNegative`, возвращающую `const double*` на первый отрицательный элемент либо `nullptr`.
3. Для нескольких вложенных блоков заранее запиши порядок создания и уничтожения объектов. Проверь прогноз с классом, печатающим сообщения из конструктора и деструктора.
4. Передай большой вектор по `const&` и объясни, кто остаётся его владельцем.

<details><summary>Подсказка</summary>

Ссылка и указатель должны быть связаны с уже существующим объектом. В поиске возвращай адрес элемента самого входного диапазона, а не адрес локальной копии. Проверяй `nullptr` перед разыменованием.

</details>

### Уровень 2. Поиск ошибок времени жизни

Для каждого сценария найди владельца и исправь контракт:

1. функция возвращает `std::span` на локальный вектор;
2. класс хранит `const std::string&` на строку, переданную временным выражением;
3. указатель на первый элемент вектора используется после серии `push_back`;
4. функция возвращает ссылку на локально вычисленный `double`;
5. лямбда захватывает локальный порог по ссылке и возвращается из функции.

<details><summary>Подсказка</summary>

Самый прямой способ исправления часто состоит в возврате значения или хранении собственного значения. Если нужна невладеющая связь, владелец должен быть явно известен внешнему коду и жить дольше наблюдателя.

</details>

### Уровень 3. RAII на практике

1. Напиши класс `ScopeTimer`, который запоминает время создания и печатает длительность в деструкторе. Запусти его в функции с несколькими путями `return`.
2. Напиши класс `ScopedSetting`, временно заменяющий значение существующей переменной и восстанавливающий старое значение в деструкторе. Запрети копирование объекта охраны.
3. Реализуй функцию чтения чисел из файла так, чтобы вычислительная функция работала со `std::istream&`. Протестируй её с `std::istringstream`.
4. Нарисуй схему владения своей программы: прямоугольниками отметь владельцев, стрелками — ссылки, указатели и `span`. Для каждой стрелки докажи, что владелец живёт дольше.

<details><summary>Подсказка</summary>

RAII-объект должен получить необходимое состояние в конструкторе и восстановить или освободить его в деструкторе. Для таймера пригодится `<chrono>`. У `ScopedSetting` можно хранить указатель или ссылку на внешнюю переменную и копию старого значения, но сам объект охраны не должен пережить эту переменную.

</details>

## 20. Вопросы для самопроверки

### Чем область видимости отличается от времени жизни?

Область видимости определяет доступность имени в коде, а время жизни — период существования объекта во время выполнения.

### В каком порядке уничтожаются локальные объекты одного блока?

В обратном порядке относительно завершённого создания.

### Означает ли `T*`, что указатель владеет объектом?

Нет. Сырой указатель сам по себе не выражает владение; в современном коде он обычно является наблюдателем.

### Когда выбирать ссылку, а когда указатель?

Ссылку — для обязательного существующего объекта. Указатель — когда допустимо отсутствие через `nullptr` или нужен переназначаемый наблюдатель.

### Продлевает ли ссылка время жизни объекта?

Обычно нет. Есть отдельные правила временных объектов, но невладеющую ссылку нельзя считать владельцем.

### Владеет ли `std::span` элементами?

Нет. Он хранит представление диапазона, поэтому исходные данные должны существовать достаточно долго.

### Почему указатель на элемент `vector` может стать недействительным?

Вектор может перевыделить память и переместить элементы, либо удалить соответствующий элемент.

### Что такое RAII?

Связывание владения ресурсом с временем жизни объекта: ресурс получается при создании и освобождается деструктором.

### Что такое Rule of Zero?

Предпочтение стандартных RAII-полей, благодаря которым классу не нужны собственные деструктор, копирование и перемещение.

### Почему `new/delete` не подходят для обычного массива значений?

Ручное управление легко приводит к утечкам, двойному освобождению и висячим адресам; `std::vector` уже безопасно решает владение массивом.

### Освободятся ли RAII-ресурсы при исключении?

Да, деструкторы полностью созданных локальных объектов вызываются при раскрутке стека.

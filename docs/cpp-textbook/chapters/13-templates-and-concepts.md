# Глава 13. Шаблоны и concepts без магии

## Зачем нужна эта глава

Ты уже постоянно пользуешься шаблонами, даже если ещё не писал их самостоятельно:

```cpp
std::vector<double>
std::optional<int>
std::unique_ptr<Processor>
```

`std::vector` — не один готовый класс для конкретного типа. Это шаблон класса, из которого компилятор создаёт нужный тип: `vector<double>`, `vector<int>` и так далее.

Шаблоны позволяют выразить алгоритм или структуру данных один раз для нескольких типов и при этом сохранить статическую проверку. Но ими легко злоупотребить. Цель этой главы — научить тебя практическому подмножеству: простым шаблонам функций и классов, понятным ограничениям через concepts и чтению базовых диагностик. Сложная метапрограмма здесь не нужна.

## Что ты будешь уметь после главы

Ты сможешь:

- объяснить, чем шаблон отличается от обычной функции и динамического полиморфизма;
- писать простой шаблон функции;
- понимать вывод параметров шаблона;
- писать небольшой шаблон класса с параметром типа и нетиповым параметром;
- ограничивать шаблон стандартным concept;
- читать простое `requires`-выражение;
- понимать, почему определения шаблонов обычно находятся в заголовке;
- распознавать преждевременное обобщение;
- не уходить в SFINAE, perfect forwarding и метапрограммирование без практической причины.

## 1. Обычная функция и шаблон функции

Обычная функция работает с конкретными типами:

```cpp
double square(double value) {
    return value * value;
}
```

Можно написать отдельную перегрузку для `float`, но реализации будут почти одинаковыми. Шаблон описывает семейство функций:

```cpp
template <typename T>
T square(T value) {
    return value * value;
}
```

При вызове:

```cpp
const int a = square(4);       // T = int
const double b = square(1.5);  // T = double
```

компилятор выводит `T` из аргумента и создаёт подходящую специализацию функции.

Шаблон не означает «любой тип обязательно сработает». Выражение `value * value` должно иметь смысл для выбранного `T`. Без явного ограничения ошибка может появиться глубоко внутри тела шаблона и выглядеть громоздко.

## 2. Вывод параметров

Обычно параметр типа выводится из аргументов:

```cpp
template <typename T>
T maximum(T left, T right);

maximum(2, 5);       // T = int
maximum(2.0, 5.0);   // T = double
```

А этот вызов неоднозначен для такого шаблона:

```cpp
maximum(2, 5.0);     // Один аргумент предлагает int, другой — double.
```

Не исправляй каждую такую ситуацию явным указанием шаблонного аргумента наугад. Сначала реши, какой контракт нужен:

- оба аргумента обязаны иметь один тип;
- допустимы разные типы с общим результатом;
- вызывающий код должен явно преобразовать значение.

Для учебного и прикладного кода первый вариант часто самый ясный.

## 3. Ограничения и concepts

Concept — именованное требование к шаблонному параметру. В C++20 стандартная библиотека предоставляет готовые concepts из `<concepts>`.

```cpp
#include <concepts>

template <std::floating_point T>
T half(T value) {
    return value / T{2};
}
```

Теперь функция принимает `float`, `double` и другие вещественные типы, но не принимает `int`. Ограничение видно прямо в интерфейсе.

Другой синтаксис записывает ограничение после списка параметров:

```cpp
template <typename T>
requires std::floating_point<T>
T half(T value) {
    return value / T{2};
}
```

Обе записи корректны. Для простого одиночного ограничения первая обычно короче.

Стандартные concepts, полезные на начальном уровне:

- `std::integral<T>` — целочисленный тип;
- `std::floating_point<T>` — вещественный тип;
- `std::same_as<T, U>` — один и тот же тип;
- `std::convertible_to<T, U>` — значение `T` можно преобразовать в `U`;
- `std::copyable<T>` — тип поддерживает требуемые операции копирования;
- `std::totally_ordered<T>` — доступны согласованные операции сравнения.

Concept проверяет свойства типа во время компиляции. Он не заменяет проверку данных во время выполнения. `std::floating_point<double>` истинно, но конкретный `double` всё равно может быть `NaN` или отрицательной частотой.

## 4. Собственный простой concept

Иногда стандартного concept недостаточно. `requires`-выражение может проверить наличие нужной операции.

```cpp
#include <concepts>

template <typename T>
concept ScalableByDouble = requires(T value, double factor) {
    { value * factor } -> std::convertible_to<T>;
};
```

Эта запись читается так: для значений `T` и `double` выражение `value * factor` должно существовать, а его результат должен преобразовываться в `T`.

Не спеши придумывать concept для каждой функции. Хорошее ограничение описывает реальную потребность алгоритма и улучшает сообщение об ошибке. Плохое ограничение просто повторяет случайные детали текущей реализации.

## 5. Шаблон класса

Шаблон класса создаёт семейство типов:

```cpp
template <typename T>
class Box {
public:
    explicit Box(T value) : value_(std::move(value)) {}
    const T& value() const noexcept { return value_; }

private:
    T value_;
};
```

`Box<int>` и `Box<std::string>` — разные типы.

Шаблон может принимать не только тип, но и значение, известное во время компиляции:

```cpp
template <typename T, std::size_t Size>
class FixedBuffer {
    std::array<T, Size> data_{};
};
```

Здесь `Size` — нетиповой параметр шаблона. `FixedBuffer<double, 16>` хранит размер в самом типе и может использовать `std::array` без динамического выделения памяти.

## 6. Где размещать определения шаблонов

Обычную функцию часто объявляют в `.hpp`, а определяют в `.cpp`. Для шаблона компилятор обычно должен видеть полное определение в месте создания конкретной специализации.

Поэтому простой шаблон обычно полностью находится в заголовке:

```cpp
// mean.hpp
#pragma once

template <typename T>
T mean(const std::vector<T>& values) {
    // Полное тело видно пользователю заголовка.
}
```

Если оставить тело только в отдельном `.cpp`, другой файл может успешно скомпилировать вызов, но затем получить ошибку линковки для отсутствующей специализации.

Существуют явные инстанцирования и другие способы организации больших шаблонов, но для начального практического уровня достаточно правила: определение шаблона держат доступным в заголовке.

## 7. Шаблон или виртуальный интерфейс

Оба механизма дают вариативность, но в разное время.

Шаблон:

- конкретный тип известен при компиляции;
- обычно нет виртуального вызова;
- разные специализации — разные типы;
- реализация должна быть видна компилятору;
- может увеличивать время сборки и размер кода.

Виртуальный интерфейс:

- конкретная реализация может выбираться во время выполнения;
- объекты доступны через общий базовый интерфейс;
- возникает виртуальный вызов и требуется корректное полиморфное время жизни;
- реализации можно скрыть за обычными `.cpp`-границами.

Не выбирай шаблон только ради потенциальной скорости. Сначала определи, когда должен происходить выбор реализации и нужен ли единый тип контейнера.

## 8. Разобранный пример: среднее для вещественного типа

Функция работает для `float`, `double` и `long double`, но намеренно отвергает целочисленный тип. Для целых чисел среднее обычно должно иметь другой тип результата, поэтому лучше не получать незаметное целочисленное деление.

```cpp
#include <concepts>
#include <iostream>
#include <numeric>
#include <optional>
#include <vector>

template <std::floating_point T>
std::optional<T> mean(const std::vector<T>& values) {
    if (values.empty()) {
        return std::nullopt;
    }

    const T sum = std::accumulate(values.begin(), values.end(), T{});
    return sum / static_cast<T>(values.size());
}

template <std::floating_point T>
void printMean(const std::vector<T>& values) {
    if (const auto result = mean(values)) {
        std::cout << *result << '\n';
    } else {
        std::cout << "no samples\n";
    }
}

int main() {
    printMean(std::vector<float>{1.0F, 2.0F, 6.0F});
    printMean(std::vector<double>{0.5, 1.5});

    // printMean(std::vector<int>{1, 2, 6});
    // Строка выше не компилируется: int не удовлетворяет floating_point.
}
```

Сборка:

```bash
clang++ -std=c++20 -Wall -Wextra -Wpedantic generic_mean.cpp -o generic_mean
./generic_mean
```

Важные детали:

- `T{}` создаёт нулевое значение нужного типа;
- начальное значение `accumulate` определяет тип накопления;
- `static_cast<T>(values.size())` делает преобразование явным;
- ограничение сообщает намерение лучше, чем ошибка внутри деления;
- пустой набор остаётся ожидаемым отсутствием результата.

## 9. Разобранный пример: окно фиксированного размера

Шаблон класса хранит последние `Capacity` вещественных отсчётов. Ёмкость известна при компиляции, а число реально добавленных элементов меняется во время выполнения.

```cpp
#include <array>
#include <concepts>
#include <cstddef>
#include <iostream>
#include <optional>

template <std::floating_point T, std::size_t Capacity>
class SampleWindow {
    static_assert(Capacity > 0, "SampleWindow capacity must be positive");

public:
    void push(T value) noexcept {
        data_[next_] = value;
        next_ = (next_ + 1) % Capacity;
        if (size_ < Capacity) {
            ++size_;
        }
    }

    std::size_t size() const noexcept {
        return size_;
    }

    static constexpr std::size_t capacity() noexcept {
        return Capacity;
    }

    std::optional<T> mean() const noexcept {
        if (size_ == 0) {
            return std::nullopt;
        }

        T sum{};
        for (std::size_t i = 0; i < size_; ++i) {
            sum += data_[i];
        }
        return sum / static_cast<T>(size_);
    }

private:
    std::array<T, Capacity> data_{};
    std::size_t next_{0};
    std::size_t size_{0};
};

int main() {
    SampleWindow<double, 3> window;
    window.push(1.0);
    window.push(2.0);
    window.push(6.0);
    window.push(10.0); // Самый старый отсчёт заменён.

    std::cout << "size = " << window.size() << '\n';
    std::cout << "capacity = " << window.capacity() << '\n';
    std::cout << "mean = " << *window.mean() << '\n';
}
```

После четвёртого `push` массив содержит последние три значения, хотя их физический порядок в кольцевом буфере может отличаться от временного. Для среднего порядок не важен.

Обрати внимание: шаблон не делает класс автоматически хорошим. Инварианты, границы и семантика окна всё равно должны быть продуманы.

## Связь с MATLAB

В MATLAB одна функция часто принимает массивы разных числовых классов, а многие проверки происходят во время выполнения. В C++ шаблон позволяет сформировать отдельную типобезопасную функцию для каждого подходящего типа ещё во время компиляции.

Различия:

- `vector<float>` и `vector<double>` — разные типы;
- ошибка неподходящего типа может быть обнаружена до запуска;
- шаблон не является динамически типизированной функцией;
- параметр размера может стать частью типа;
- операция, допустимая для `double`, не обязана существовать для произвольного пользовательского типа;
- обобщение не создаёт broadcasting или матричную семантику автоматически.

Не пытайся заменить шаблонами всё, что MATLAB решает динамически. Иногда обычная функция для `double` — наиболее честный первый вариант. Обобщай после появления второго реального типа или алгоритма с ясными общими требованиями.

## Типичные ошибки

1. **Писать шаблон до появления второго варианта использования.** Возможно, обобщение вообще не понадобится.
2. **Обещать «любой тип», хотя тело требует арифметики, сравнения или копирования.** Добавь разумный concept или сузь интерфейс.
3. **Смешивать `int` и `double` в одном параметре `T` и удивляться ошибке вывода.** Сначала зафиксируй контракт типов.
4. **Инициализировать `accumulate` числом `0` для вещественного контейнера.** Тип накопления может стать целым; используй `T{}` или нужный явный тип.
5. **Размещать определение шаблона только в `.cpp`.** Пользователь шаблона может не увидеть тело при инстанцировании.
6. **Считать concept проверкой значений.** Он проверяет тип, но не положительность частоты и не конечность конкретного числа.
7. **Делать concept чрезмерно строгим.** Требуй только операции, реально необходимые алгоритму.
8. **Использовать шаблоны вместо простого виртуального интерфейса при runtime-выборе.** Это разные виды вариативности.
9. **Пытаться читать всю длинную диагностику сразу.** Найди сначала свой файл, строку вызова и первое неудовлетворённое требование.
10. **Уходить в SFINAE и специализации ради короткой функции.** C++20 concepts обычно дают более прямой интерфейс.
11. **Использовать `auto` так, что важный конкретный тип становится невидимым.** В учебном коде тип иногда стоит записать явно.
12. **Полагать, что шаблон всегда быстрее.** Производительность нужно измерять, а архитектуру выбирать по контракту.

## Как читать ошибку шаблона

Сообщение может занимать много строк. Читай его в таком порядке:

1. Найди первую строку в своём исходном файле, где вызван шаблон.
2. Найди типы, которые компилятор вывел для параметров.
3. Найди фразу вроде `constraints not satisfied`, `required expression is invalid` или `no matching function`.
4. Определи первое нарушенное требование, а не последнюю внутреннюю ошибку библиотеки.
5. Сократи пример до одного вызова и минимального типа.

Не исправляй диагностику случайными преобразованиями. Сначала реши, должен ли этот тип вообще поддерживаться.

## Упражнения

### Уровень 1. Ограниченный максимум

Напиши шаблон:

```cpp
template <std::totally_ordered T>
const T& maximum(const T& left, const T& right);
```

Проверь его на `int`, `double` и `std::string`. Объясни, почему функция возвращает ссылку и какое ограничение времени жизни из этого следует.

<details>
<summary>Подсказка</summary>

Достаточно сравнения `left < right`. Нельзя сохранять возвращённую ссылку дольше объектов-аргументов. Для временных аргументов интерфейс со ссылкой требует особой осторожности; попробуй также версию с возвратом по значению и сравни контракты.

</details>

### Уровень 2. Сумма чисел

Напиши concept `Number`, принимающий целые и вещественные стандартные типы, и функцию:

```cpp
template <Number T>
T sum(const std::vector<T>& values);
```

Проверь `vector<int>` и `vector<double>`. Добавь комментарий о риске переполнения целого типа. Затем создай намеренно неподходящий вызов и прочитай диагностику constraints.

<details>
<summary>Подсказка</summary>

Concept можно определить как логическое «или» между `std::integral<T>` и `std::floating_point<T>`. Для `accumulate` используй `T{}`. Concept не защищает от переполнения.

</details>

### Уровень 3. Фиксированный буфер

Создай шаблон `FixedBuffer<T, Capacity>` с операциями:

- `push(const T&)`;
- `size()`;
- `capacity()`;
- `at(index)` с проверкой;
- `full()`.

После заполнения `push` должен либо бросать понятное исключение, либо возвращать `bool`. Сам выбери контракт и обоснуй его. Буфер не должен использовать динамическую память.

<details>
<summary>Подсказка</summary>

Внутри подойдёт `std::array<T, Capacity>` и отдельный счётчик реально занятых элементов. Запрети нулевую ёмкость через `static_assert`. Не реализуй собственные итераторы — это уже другая задача.

</details>

## Вопросы для самопроверки

1. Когда компилятор создаёт конкретную функцию из шаблона?
2. Является ли `std::vector<int>` тем же типом, что `std::vector<double>`?
3. Что делает concept?
4. Проверит ли `std::floating_point<T>`, что значение положительно?
5. Почему тело шаблона обычно находится в заголовке?
6. Чем шаблонный выбор отличается от виртуального вызова?
7. Что такое нетиповой параметр шаблона?
8. Почему `std::accumulate(..., 0)` может быть ошибкой для `double`?
9. Нужно ли делать шаблоном каждую функцию из одной строки?
10. С какой части длинной диагностики шаблона начать чтение?

<details>
<summary>Краткие ответы</summary>

1. Когда в программе требуется специализация с конкретными параметрами.
2. Нет, это разные специализации и разные типы.
3. Ограничивает допустимые типы и делает требования интерфейса явными.
4. Нет, concept проверяет свойства типа, а не конкретное значение.
5. Компилятору нужно видеть определение в месте инстанцирования.
6. Шаблон обычно выбирается при компиляции, виртуальная реализация — во время выполнения.
7. Параметр-значение, известный при компиляции, например размер массива.
8. Начальное значение задаёт целый тип накопления и может обрезать дробную часть.
9. Нет; сначала должна существовать реальная потребность в нескольких типах.
10. Со своего места вызова, выведенных типов и первого неудовлетворённого ограничения.

</details>

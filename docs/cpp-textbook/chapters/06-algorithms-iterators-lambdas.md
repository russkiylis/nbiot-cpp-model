# Глава 6. Алгоритмы, итераторы и лямбда-функции

## Зачем нужна эта тема

Ты уже умеешь хранить последовательность значений в `std::vector` и обрабатывать её циклом. Этого достаточно, чтобы решить почти любую небольшую задачу, но по мере роста программы циклы начинают повторяться: найти значение, посчитать подходящие элементы, преобразовать все элементы, отсортировать данные.

Стандартная библиотека C++ уже содержит такие операции. Они называются **алгоритмами**. Вместо того чтобы каждый раз заново писать механику цикла, ты указываешь:

- над каким диапазоном работать;
- что именно искать или преобразовывать;
- какое условие считать выполненным.

Для описания диапазона алгоритмы используют **итераторы**, а небольшое условие или преобразование удобно передавать как **лямбда-функцию**.

Эта тройка — алгоритм, итератор и лямбда — помогает писать код, в котором лучше видно намерение. Выражение `std::count_if(...)` сразу говорит: «посчитай элементы, удовлетворяющие условию». В обычном цикле это намерение ещё нужно распознать среди индексов, счётчиков и ветвлений.

## Результаты обучения

После этой главы ты сможешь:

- объяснить, что такое итератор и диапазон `[begin, end)`;
- безопасно использовать `begin()`, `end()` и итераторы, возвращаемые алгоритмами;
- применять `std::find`, `std::count_if`, `std::transform`, `std::sort` и `std::accumulate`;
- писать лямбда-функции с параметрами, возвращаемым значением и захватами;
- выбирать между обычным циклом и алгоритмом STL;
- понимать, когда операция меняет исходный контейнер;
- распознавать основные причины инвалидирования итераторов;
- использовать несколько простых возможностей C++20 ranges без сложной магии.

## 1. Алгоритм не владеет данными

Контейнер и алгоритм выполняют разные роли:

- `std::vector<double>` хранит значения и управляет памятью;
- `std::sort` переставляет элементы в переданном диапазоне;
- `std::find` просматривает диапазон и возвращает позицию;
- `std::transform` применяет операцию к элементам.

Алгоритм обычно не знает, что перед ним именно `std::vector`. Он получает две границы диапазона. Поэтому один и тот же алгоритм можно применять к разным контейнерам.

Для большинства алгоритмов нужны отдельные заголовки:

- `<algorithm>` — поиск, сортировка, преобразование и другие алгоритмы;
- `<numeric>` — `std::accumulate` и некоторые численные алгоритмы;
- `<iterator>` — дополнительные средства работы с итераторами.

## 2. Что такое итератор

Итератор — объект, обозначающий позицию в последовательности. Он похож на обобщённый указатель:

- `*it` даёт элемент в текущей позиции;
- `++it` перемещает итератор к следующему элементу;
- `it1 == it2` сравнивает позиции.

У контейнера есть две важные операции:

```text
values.begin()  — позиция первого элемента;
values.end()    — позиция сразу после последнего элемента.
```

Диапазон записывают как `[begin, end)`: левая граница включена, правая не включена. Это та же идея полуинтервала, которую ты уже встречал в индексах от `0` до `size - 1`.

Для вектора из трёх элементов позиции выглядят так:

```text
begin()                                      end()
   |                                           |
   v                                           v
 [ 12 ] [ 25 ] [ 40 ] [ позиция после данных ]
```

`end()` — не последний элемент. Разыменовывать `*values.end()` нельзя: это неопределённое поведение.

### Итератор, возвращённый поиском

Алгоритм поиска возвращает итератор на найденный элемент. Если элемент не найден, возвращается правая граница переданного диапазона.

Логика использования всегда двухэтапная:

1. сравнить результат с `end()`;
2. только после успешной проверки разыменовать итератор.

## 3. Основные алгоритмы

### Поиск: `std::find` и `std::find_if`

`std::find` ищет конкретное значение. `std::find_if` ищет первый элемент, для которого условие вернуло `true`.

Оба алгоритма возвращают итератор. Они не выбрасывают исключение, если ничего не нашли.

### Подсчёт: `std::count` и `std::count_if`

`std::count` считает элементы, равные заданному значению. `std::count_if` считает элементы, удовлетворяющие условию.

### Преобразование: `std::transform`

`std::transform` читает элементы входного диапазона и записывает результаты, начиная с указанной выходной позиции.

Важный момент: алгоритм не увеличивает выходной `std::vector` автоматически. Есть два обычных варианта:

- заранее создать вектор нужного размера и писать в `result.begin()`;
- использовать `std::back_inserter(result)`, который вызывает `push_back` для результатов.

### Сортировка: `std::sort`

`std::sort` меняет порядок элементов непосредственно в переданном контейнере. Если исходный порядок нужен дальше, сначала сделай осознанную копию.

По умолчанию значения сортируются по возрастанию. Третий аргумент позволяет передать другое правило сравнения.

Правило сравнения должно отвечать на вопрос «должен ли левый элемент стоять раньше правого?». Для строгого порядка обычно используют `<` или `>` — не `<=` и не `>=`.

### Накопление: `std::accumulate`

`std::accumulate` последовательно объединяет элементы, начиная с начального значения. Для суммы это значение обычно `0.0` или `0`.

Тип начального значения важен. Если суммируются `double`, но начальное значение записано как целое `0`, накопление тоже может выполняться в целом типе и терять дробную часть. Пиши `0.0`, когда нужен `double`.

## 4. Лямбда-функции

Лямбда — небольшая функция без отдельного имени. Общая форма:

```text
[захваты](параметры) -> возвращаемый_тип {
    тело
}
```

Часто компилятор сам выводит возвращаемый тип, поэтому часть после `->` можно опустить.

Простейшая лямбда-проверка:

```cpp
[](double value) {
    return value > 0.0;
}
```

Пустые квадратные скобки `[]` означают, что лямбда не использует локальные переменные из окружающей функции.

### Захват по значению

```cpp
[threshold](double value) {
    return value > threshold;
}
```

Лямбда получает собственную копию `threshold`. Последующее изменение исходной переменной не меняет уже сохранённую копию внутри лямбды.

### Захват по ссылке

```cpp
[&counter](double value) {
    if (value > 0.0) {
        ++counter;
    }
}
```

Лямбда обращается к исходному `counter`. Это позволяет изменять его, но ссылка остаётся корректной только пока исходная переменная существует.

Захваты `[=]` и `[&]` означают «захватывать используемые переменные автоматически по значению» и «по ссылке». Для учебного и рабочего кода чаще понятнее перечислять важные захваты явно.

### Предикат

Функцию, возвращающую `bool`, часто называют **предикатом**. Например, предикат может проверять, превышает ли отсчёт порог или является ли число чётным.

### Компаратор

Функцию, задающую порядок двух элементов, называют **компаратором**. Она принимает два значения и возвращает `true`, если первое должно располагаться раньше второго.

## 5. Полностью компилируемый пример: поиск, подсчёт и сортировка

Программа находит первый отсчёт выше порога, считает все такие отсчёты и печатает их в порядке убывания.

```cpp
#include <algorithm>
#include <functional>
#include <iostream>
#include <vector>

int main() {
    const std::vector<double> samples{0.4, 1.8, -0.2, 2.7, 1.1};
    const double threshold = 1.5;

    const auto firstHigh = std::find_if(
        samples.begin(),
        samples.end(),
        [threshold](double sample) {
            return sample > threshold;
        });

    if (firstHigh != samples.end()) {
        const auto index = std::distance(samples.begin(), firstHigh);
        std::cout << "Первый отсчёт выше порога: индекс "
                  << index << ", значение " << *firstHigh << '\n';
    } else {
        std::cout << "Отсчётов выше порога нет\n";
    }

    const auto highCount = std::count_if(
        samples.begin(),
        samples.end(),
        [threshold](double sample) {
            return sample > threshold;
        });

    std::vector<double> sorted = samples;
    std::sort(sorted.begin(), sorted.end(), std::greater<>{});

    std::cout << "Количество: " << highCount << '\n';
    std::cout << "По убыванию:";
    for (double sample : sorted) {
        std::cout << ' ' << sample;
    }
    std::cout << '\n';
}
```

Разбор:

1. `samples` объявлен как `const`, поэтому алгоритмы могут читать его, но не менять.
2. `firstHigh` имеет сложный тип итератора, поэтому удобно использовать `auto`.
3. До `*firstHigh` выполняется проверка `firstHigh != samples.end()`.
4. `std::distance` переводит позицию итератора в расстояние от начала диапазона.
5. Сортируется копия `sorted`, а исходные данные сохраняют порядок.
6. `std::greater<>` задаёт порядок по убыванию.

Пример сборки:

```bash
c++ -std=c++20 -Wall -Wextra -Wpedantic example.cpp -o example
./example
```

## 6. Полностью компилируемый пример: преобразование и среднее

Программа переводит температуры из градусов Цельсия в градусы Фаренгейта и считает среднее значение.

```cpp
#include <algorithm>
#include <iostream>
#include <iterator>
#include <numeric>
#include <vector>

int main() {
    const std::vector<double> celsius{-10.0, 0.0, 18.5, 25.0};
    std::vector<double> fahrenheit;
    fahrenheit.reserve(celsius.size());

    std::transform(
        celsius.begin(),
        celsius.end(),
        std::back_inserter(fahrenheit),
        [](double value) {
            return value * 9.0 / 5.0 + 32.0;
        });

    const double sum = std::accumulate(
        fahrenheit.begin(),
        fahrenheit.end(),
        0.0);

    if (!fahrenheit.empty()) {
        const double average = sum / static_cast<double>(fahrenheit.size());
        std::cout << "Среднее: " << average << " F\n";
    }

    std::cout << "Значения:";
    for (double value : fahrenheit) {
        std::cout << ' ' << value;
    }
    std::cout << '\n';
}
```

Разбор:

1. `fahrenheit` сначала пуст.
2. `reserve` заранее выделяет достаточно памяти, но не создаёт элементы и не меняет `size()`.
3. `std::back_inserter` добавляет каждый результат через `push_back`.
4. Лямбда не нуждается в захватах.
5. Начальное значение накопления записано как `0.0`, поэтому сумма вычисляется как `double`.
6. Перед делением проверяется, что вектор не пуст.

## 7. Связь с MATLAB

В MATLAB многие операции изначально ориентированы на массивы:

```matlab
high = samples(samples > threshold);
fahrenheit = celsius * 9 / 5 + 32;
sorted = sort(samples, 'descend');
```

В C++ стандартные контейнеры не поддерживают такое математическое выражение напрямую. Вместо этого ты выбираешь алгоритм и явно задаёшь диапазон.

Полезные соответствия:

| Намерение | MATLAB | C++ |
|---|---|---|
| Найти значение | `find(...)` | `std::find`, `std::find_if` |
| Посчитать подходящие | `sum(condition)` | `std::count_if` |
| Преобразовать массив | операция над массивом | `std::transform` |
| Отсортировать | `sort` | `std::sort` |
| Суммировать | `sum` | `std::accumulate` |
| Условие на элемент | анонимная функция | лямбда-функция |

Есть важные различия:

- MATLAB часто создаёт новый массив автоматически; в C++ ты явно выбираешь место для результата.
- Индексы MATLAB начинаются с 1, а позиции C++ — с 0.
- Итератор — не число индекса, хотя для `std::vector` между ними можно вычислить расстояние.
- `std::sort` меняет переданный диапазон, тогда как в MATLAB результат сортировки обычно присваивают новой переменной.
- C++ позволяет выбирать тип контейнера и точно контролировать копирования.

## 8. C++20 ranges: первое знакомство

В C++20 часть алгоритмов доступна в пространстве имён `std::ranges`. Для некоторых из них можно передать контейнер целиком:

```cpp
const auto it = std::ranges::find(values, 42);
std::ranges::sort(values);
```

Views позволяют лениво описывать последовательность преобразований. Например, `std::views::filter` представляет только подходящие элементы, не создавая новый вектор сразу.

У views есть важное ограничение: они обычно не владеют исходными данными. Нельзя позволять view пережить контейнер, на который он ссылается. На первом этапе используй ranges локально и не сохраняй сложные views в полях классов.

Классические алгоритмы с `begin()` и `end()` всё ещё важны: они встречаются в огромном количестве существующего C++-кода и хорошо показывают устройство диапазона.

## 9. Когда обычный цикл лучше

Не нужно заменять каждый цикл алгоритмом. Обычный цикл может быть яснее, если ты:

- одновременно вычисляешь несколько связанных характеристик;
- зависишь от сложного состояния предыдущих итераций;
- должен досрочно выйти из нескольких уровней логики;
- реализуешь алгоритм, для которого нет понятного стандартного аналога.

Хороший вопрос при выборе: «Какой вариант яснее выражает намерение и не скрывает важное состояние?»

## 10. Инвалидирование итераторов

Итератор корректен не всегда. Операция, меняющая контейнер, может сделать ранее полученные итераторы недействительными.

Особенно важно для `std::vector`:

- `push_back` может перевыделить память и инвалидировать все итераторы, ссылки и указатели на элементы;
- `insert` и `erase` могут инвалидировать позиции начиная с места изменения;
- `clear` уничтожает элементы, поэтому итераторы на них больше не действуют;
- сортировка не уничтожает итераторы вектора, но значения оказываются в других позициях.

Не сохраняй итератор на элемент, затем не добавляй элементы в вектор и не используй старый итератор без проверки правил контейнера.

## 11. Типичные ошибки

### Разыменование `end()`

Поиск может ничего не найти. Сначала сравни результат с правой границей, потом используй `*it`.

### Использование `<=` в компараторе сортировки

Компаратор должен задавать строгий порядок. Для равных значений `compare(a, a)` обязан вернуть `false`.

### Целое начальное значение в `accumulate`

Для суммы `double` используй `0.0`, иначе дробная часть может теряться на каждом шаге.

### Запись в пустой выходной вектор через `result.begin()`

У пустого вектора нет элементов, в которые можно записать. Либо создай нужный размер, либо используй `std::back_inserter`.

### Неожиданное изменение исходных данных

`std::sort`, `std::reverse` и многие другие алгоритмы меняют элементы. Сделай копию, если исходный порядок нужен дальше.

### Захват локальной переменной по ссылке в долгоживущей лямбде

Если лямбда сохраняется и вызывается после выхода из функции, ссылка на локальную переменную становится висячей.

### Изменение вектора во время обхода

`push_back`, `insert` или `erase` могут инвалидировать текущий итератор. Для `erase` используй итератор, который возвращает сама операция удаления, либо подходящий стандартный алгоритм.

### Слишком сложная лямбда

Если в лямбде много ветвлений и несколько задач, вынеси её в отдельную именованную функцию. Небольшая лямбда удобна, пока её назначение видно сразу.

## 12. Упражнения

### Уровень 1. Закрепление

1. Для `std::vector<int>` найди первое отрицательное число. Если его нет, напечатай отдельное сообщение.
2. Посчитай количество чётных значений через `std::count_if`.
3. Создай новый вектор, содержащий квадраты исходных значений, через `std::transform`.
4. Отсортируй копию вектора по убыванию, сохранив исходный порядок.
5. Посчитай сумму `std::vector<double>` через `std::accumulate`.

<details><summary>Подсказка</summary>

Для проверки чётности используй остаток от деления на 2. Для выходного вектора выбери либо заранее заданный размер, либо `std::back_inserter`. Не разыменовывай результат поиска до сравнения с `end()`.

</details>

### Уровень 2. Самостоятельное комбинирование

1. Напиши функцию, возвращающую новый вектор только со значениями из закрытого диапазона `[low, high]`.
2. Найди медиану набора чисел. Исходный вектор менять нельзя. Определи поведение для пустого набора.
3. Получи индексы всех элементов, превышающих порог. Подумай, нужен ли здесь алгоритм или обычный индексный цикл яснее.
4. Отсортируй строки сначала по длине, а при одинаковой длине — по алфавиту.
5. Реализуй функцию `allFinite`, проверяющую, что все `double` являются конечными. Найди подходящий алгоритм семейства `all/any/none`.

<details><summary>Подсказка</summary>

Для фильтрации пригодится `std::copy_if`. Медиану удобно искать в отсортированной копии. Компаратор строк должен при равной длине переходить ко второму правилу. Для проверки `double` посмотри на `std::isfinite` из `<cmath>`.

</details>

### Уровень 3. Задачи со спецификацией

1. Реализуй обработку сигнала: отбрось значения, модуль которых ниже порога, умножь остальные на коэффициент и отсортируй по убыванию абсолютного значения. Исходный сигнал должен сохраниться.
2. Построй гистограмму целых значений: для каждого встреченного числа верни количество его появлений. Затем выведи пары в порядке возрастания значения.
3. Сравни две реализации скользящего среднего: прямую с вложенным циклом и версию со скользящей суммой. Проверь одинаковость результатов с допуском и измерь время на большом векторе.
4. Создай функцию, принимающую порог и возвращающую лямбду-предикат. Проверь, что предикат безопасно работает после завершения функции-создателя.

<details><summary>Подсказка</summary>

Раздели конвейер на несколько простых шагов и храни промежуточный результат только там, где это делает код понятнее. Для гистограммы пригодится ассоциативный контейнер. В возвращаемой лямбде порог нужно захватить по значению, иначе ссылка на локальную переменную станет недействительной.

</details>

## 13. Вопросы для самопроверки

### Что обозначает `end()`?

Позицию сразу после последнего элемента. Разыменовывать её нельзя.

### Как алгоритм сообщает, что поиск не удался?

Обычно возвращает итератор, равный правой границе переданного диапазона.

### Чем `reserve` отличается от `resize`?

`reserve` меняет ёмкость, но не количество элементов. `resize` меняет `size()` и создаёт или удаляет элементы.

### Почему для суммы `double` в `accumulate` лучше передать `0.0`?

Тип начального значения влияет на тип накопителя. `0.0` задаёт накопление в `double`.

### Что означает захват `[threshold]`?

Лямбда сохраняет собственную копию переменной `threshold`.

### Чем опасен захват по ссылке?

Лямбда может пережить исходную переменную и получить висячую ссылку.

### Меняет ли `std::sort` исходный контейнер?

Да, он переставляет элементы непосредственно в переданном диапазоне.

### Всегда ли алгоритм лучше цикла?

Нет. Выбирай вариант, который яснее выражает намерение и состояние вычисления.

### Почему нельзя использовать `<=` в компараторе `std::sort`?

Такое сравнение не задаёт строгий порядок: для равного элемента оно возвращает `true`, нарушая требования алгоритма.

### Владеет ли ranges-view исходными элементами?

Обычно нет. Он представляет вычисление над существующим диапазоном, поэтому срок жизни данных должен быть достаточным.

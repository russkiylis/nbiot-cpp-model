# Глава 7. Структуры, перечисления и классы

## Зачем нужна эта тема

Пока данные можно хранить в отдельных переменных:

```text
частота дискретизации;
число отсчётов;
имя сигнала;
сами отсчёты.
```

Но эти значения описывают один объект и должны согласовываться друг с другом. Если передавать их по отдельности, легко перепутать параметры или создать невозможное состояние, например сигнал с отрицательной частотой дискретизации.

C++ предлагает несколько уровней моделирования:

- `struct` объединяет связанные данные;
- `enum class` задаёт конечный набор именованных вариантов;
- `class` объединяет состояние и операции и может защищать свои инварианты;
- композиция позволяет строить сложный объект из более простых.

ООП начинается не с наследования. Его практическая основа — объект с понятной ответственностью, корректным состоянием и небольшим публичным интерфейсом.

## Результаты обучения

После этой главы ты сможешь:

- объединять связанные поля в `struct`;
- выбирать между `struct` и `class`;
- заменять «магические числа» типом `enum class`;
- писать конструктор со списком инициализации;
- разделять публичный интерфейс и закрытое состояние;
- формулировать и защищать инварианты класса;
- писать `const`-методы;
- применять композицию вместо необоснованного наследования;
- понимать различие между объектом, классом и экземпляром;
- проектировать небольшой класс до написания его реализации.

## 1. `struct`: одно значение из нескольких частей

Структура объявляет новый тип, состоящий из именованных полей:

```cpp
struct Measurement {
    double timeSeconds{};
    double value{};
};
```

Теперь `Measurement` — такой же тип, как `int` или `double`, только определённый тобой.

```cpp
Measurement sample{0.25, 18.7};
std::cout << sample.timeSeconds;
```

Фигурные скобки инициализируют поля по порядку объявления. Значения `{}` у полей дают безопасную инициализацию по умолчанию: числовые поля становятся нулевыми.

Структура удобна, когда:

- поля вместе образуют небольшое значение;
- допустимо непосредственное чтение и изменение полей;
- между полями нет сложных правил согласованности;
- тип служит результатом вычисления или записью данных.

Примеры хороших структур:

- точка с координатами `x`, `y`;
- интервал `minimum`, `maximum`;
- запись измерения `time`, `value`;
- результат статистики `mean`, `rms`, `count`.

Структура может содержать методы, конструкторы и закрытые поля. Единственное языковое различие между `struct` и `class` — доступ по умолчанию:

- у `struct` члены по умолчанию `public`;
- у `class` члены по умолчанию `private`.

На практике `struct` обычно используют для простых открытых данных, а `class` — когда состояние нужно защищать правилами.

## 2. `enum class`: конечный набор вариантов

Представим режим фильтра:

```text
0 — выключен;
1 — сглаживание;
2 — медианный режим.
```

Такой код опирается на память программиста. Число `2` само ничего не объясняет, а любое другое целое может случайно попасть в функцию.

Именованное перечисление выражает допустимые варианты явно:

```cpp
enum class FilterMode {
    off,
    movingAverage,
    median
};
```

Использование:

```cpp
FilterMode mode = FilterMode::movingAverage;
```

Преимущества `enum class`:

- имена находятся в области типа: `FilterMode::off`;
- значение нельзя неявно смешать с обычным `int`;
- компилятор помогает проверить `switch`;
- интерфейс функции показывает допустимую категорию аргумента.

### `switch` по перечислению

```cpp
switch (mode) {
case FilterMode::off:
    // ...
    break;
case FilterMode::movingAverage:
    // ...
    break;
case FilterMode::median:
    // ...
    break;
}
```

Если перечислены все варианты, ветку `default` иногда полезно не добавлять: тогда компилятор с подходящими предупреждениями сообщит, что после расширения `enum class` один вариант не обработан.

## 3. Класс и объект

**Класс** — описание нового типа: его данных, операций и правил. **Объект** — конкретный экземпляр этого типа.

```text
Класс:        Signal
Объекты:      referenceSignal, noisySignal, filteredSignal
```

Класс обычно состоит из двух частей:

- публичный интерфейс — то, чем разрешено пользоваться внешнему коду;
- закрытая реализация — данные и вспомогательные детали.

```cpp
class Counter {
public:
    void increment() {
        ++value_;
    }

    [[nodiscard]] int value() const {
        return value_;
    }

private:
    int value_{0};
};
```

Закрытое поле нельзя изменить напрямую. Внешний код может только вызвать разрешённые операции.

Суффикс `_` в `value_` — распространённое, но не обязательное соглашение для полей класса. Главное — соблюдать один стиль последовательно.

## 4. Инвариант

Инвариант — условие, которое остаётся истинным для каждого корректного объекта после конструктора и после каждого публичного метода.

Примеры:

- частота дискретизации строго положительна;
- нижняя граница диапазона не больше верхней;
- размер матрицы согласован с количеством элементов;
- банковский счёт не может выйти за разрешённый лимит;
- имя обязательного объекта не пустое.

Класс полезен, когда он не позволяет создать или сохранить некорректное состояние.

Плохой интерфейс:

```text
создать пустой объект;
отдельно установить ширину;
отдельно установить высоту;
отдельно загрузить данные;
надеяться, что размеры совпали.
```

Более надёжная идея: конструктор сразу принимает обязательные данные, проверяет их и создаёт полностью готовый объект.

## 5. Конструктор и список инициализации

Конструктор вызывается при создании объекта. У него нет возвращаемого типа, а имя совпадает с именем класса.

Поля нужно инициализировать в списке перед телом конструктора:

```cpp
class Range {
public:
    Range(double minimum, double maximum)
        : minimum_(minimum), maximum_(maximum) {
        // Проверка инварианта
    }

private:
    double minimum_;
    double maximum_;
};
```

Это не просто другой синтаксис присваивания. До входа в тело конструктора поля уже должны быть созданы. Список инициализации задаёт, как именно их создавать.

Поля фактически инициализируются в порядке объявления в классе, а не в порядке записи в списке. Поэтому лучше сохранять одинаковый порядок.

Если конструктор не может создать корректный объект, нормальный способ сообщить об этом — выбросить исключение, например `std::invalid_argument`.

## 6. Методы и `const`

Метод с `const` после списка параметров обещает не изменять наблюдаемое состояние объекта:

```cpp
double width() const;
```

Такой метод можно вызвать у `const`-объекта. Методы чтения и вычисления характеристик обычно должны быть `const`.

Сравни:

```text
range.width()       — читает состояние;
range.shift(2.0)    — изменяет состояние.
```

Если забыть `const`, класс становится неудобным: даже безопасную операцию чтения нельзя выполнить через `const Range&`.

## 7. Геттеры, сеттеры и полезный интерфейс

Инкапсуляция не означает «сделать все поля закрытыми, а затем написать для каждого `get` и `set`».

Безусловный сеттер может разрушить инвариант:

```text
setMinimum(10);
setMaximum(5);   // объект оказался некорректным
```

Иногда лучше предоставить предметную операцию:

- `shift(delta)` сдвигает обе границы;
- `resize(rows, columns)` согласованно меняет матрицу;
- `appendSample(value)` добавляет отсчёт;
- `rename(newName)` проверяет новое имя.

Геттер тоже не всегда должен возвращать копию. Для большого `std::vector` копирование может быть дорогим. В зависимости от задачи можно вернуть:

- `const std::vector<double>&` — ссылку только для чтения;
- `std::span<const double>` — невладеющее представление диапазона;
- вычисленное значение по копии, если оно маленькое.

Возвращать неконстантную ссылку на внутренний контейнер опасно: внешний код сможет обойти проверки класса.

## 8. Полностью компилируемый пример: `struct` и `enum class`

Программа хранит измерения, определяет их состояние относительно границ и считает количество тревожных значений.

```cpp
#include <algorithm>
#include <iostream>
#include <iterator>
#include <string_view>
#include <vector>

struct Measurement {
    double timeSeconds{};
    double value{};
};

enum class Level {
    low,
    normal,
    high
};

Level classify(double value, double lowLimit, double highLimit) {
    if (value < lowLimit) {
        return Level::low;
    }
    if (value > highLimit) {
        return Level::high;
    }
    return Level::normal;
}

std::string_view toString(Level level) {
    switch (level) {
    case Level::low:
        return "низкий";
    case Level::normal:
        return "нормальный";
    case Level::high:
        return "высокий";
    }
    return "неизвестный";
}

int main() {
    const std::vector<Measurement> measurements{
        {0.0, 18.5},
        {0.5, 22.0},
        {1.0, 29.4},
        {1.5, 16.8}
    };

    const double lowLimit = 18.0;
    const double highLimit = 27.0;

    for (const Measurement& measurement : measurements) {
        const Level level = classify(
            measurement.value,
            lowLimit,
            highLimit);

        std::cout << measurement.timeSeconds << " s: "
                  << measurement.value << " — "
                  << toString(level) << '\n';
    }

    const auto alarmCount = std::count_if(
        measurements.begin(),
        measurements.end(),
        [lowLimit, highLimit](const Measurement& measurement) {
            return classify(measurement.value, lowLimit, highLimit)
                != Level::normal;
        });

    std::cout << "Тревожных измерений: " << alarmCount << '\n';
}
```

Что здесь важно:

1. `Measurement` — простая запись без сложного инварианта, поэтому открытые поля уместны.
2. `Level` нельзя случайно смешать с обычным целым числом.
3. Функция `classify` возвращает предметный тип, а не неясный код `-1`, `0` или `1`.
4. `toString` централизует текстовое представление вариантов.
5. В цикле измерение передаётся по `const&`, без копирования и без возможности изменения.

## 9. Полностью компилируемый пример: класс с инвариантом

Класс `Signal` хранит отсчёты и частоту дискретизации. Частота должна быть положительной.

```cpp
#include <iostream>
#include <span>
#include <stdexcept>
#include <string>
#include <utility>
#include <vector>

class Signal {
public:
    Signal(std::vector<double> samples,
           double sampleRateHz,
           std::string name)
        : samples_(std::move(samples)),
          sampleRateHz_(sampleRateHz),
          name_(std::move(name)) {
        if (sampleRateHz_ <= 0.0) {
            throw std::invalid_argument(
                "Частота дискретизации должна быть положительной");
        }
        if (name_.empty()) {
            throw std::invalid_argument("Имя сигнала не должно быть пустым");
        }
    }

    [[nodiscard]] std::size_t size() const {
        return samples_.size();
    }

    [[nodiscard]] double sampleRateHz() const {
        return sampleRateHz_;
    }

    [[nodiscard]] double durationSeconds() const {
        return static_cast<double>(samples_.size()) / sampleRateHz_;
    }

    [[nodiscard]] const std::string& name() const {
        return name_;
    }

    [[nodiscard]] std::span<const double> samples() const {
        return samples_;
    }

    void rename(std::string newName) {
        if (newName.empty()) {
            throw std::invalid_argument("Имя сигнала не должно быть пустым");
        }
        name_ = std::move(newName);
    }

private:
    std::vector<double> samples_;
    double sampleRateHz_;
    std::string name_;
};

int main() {
    Signal signal{{0.0, 0.5, 1.0, 0.5}, 2.0, "test"};

    std::cout << signal.name() << ": "
              << signal.size() << " отсчёта, "
              << signal.durationSeconds() << " s\n";

    std::cout << "Данные:";
    for (double sample : signal.samples()) {
        std::cout << ' ' << sample;
    }
    std::cout << '\n';

    signal.rename("renamed");
    std::cout << "Новое имя: " << signal.name() << '\n';
}
```

Разбор:

1. Конструктор принимает обязательные данные и сразу проверяет инварианты.
2. Вектор и строка передаются по значению, а затем перемещаются в поля. Это даёт простой и безопасный интерфейс владения.
3. Все методы чтения отмечены `const`.
4. `samples()` возвращает только представление для чтения. Внешний код не может заменить элементы через этот интерфейс.
5. Вместо общего `setName` используется предметная операция `rename`, которая сохраняет инвариант.
6. Сеттер частоты не добавлен: если такой сценарий не нужен предметной области, не нужно расширять интерфейс заранее.

## 10. Связь с MATLAB

В MATLAB структура тоже группирует именованные поля:

```matlab
measurement.timeSeconds = 0.25;
measurement.value = 18.7;
```

В C++ состав полей известен при компиляции. Опечатка в имени поля становится ошибкой компиляции, а все объекты одного типа имеют одну объявленную структуру.

MATLAB поддерживает `classdef`, свойства и методы. Но при переходе важно помнить о различиях:

- в C++ объект обычно имеет семантику значения;
- присваивание обычного объекта создаёт независимую копию его состояния;
- доступ `private` проверяется компилятором;
- конструктор может гарантировать инвариант;
- `const` явно отделяет операции чтения;
- тип `enum class` строже, чем числовой код режима;
- контейнеры и строки сами управляют памятью как части объекта.

В MATLAB классы часто бывают handle-классами, где две переменные могут ссылаться на один изменяемый объект. Обычный C++-объект ведёт себя скорее как числовое значение: после `Signal b = a;` объект `b` является отдельной копией. Подробно копирование будет разобрано позже.

## 11. Композиция

Композиция выражает отношение «содержит»:

```text
Recording содержит несколько Signal.
Experiment содержит Configuration и Results.
Pipeline содержит последовательность Transform.
```

Если объект логически состоит из частей, поля и контейнеры обычно являются самым прямым решением.

Наследование выражает более сильное отношение «является разновидностью». Его стоит вводить только тогда, когда производный объект действительно можно безопасно использовать везде, где ожидается базовый тип, и нужен общий полиморфный интерфейс.

Не наследуй класс только ради повторного использования двух полей. На начальном этапе предпочитай композицию: она проще показывает владение и создаёт меньше скрытых связей.

## 12. Ответственность класса

Хороший класс можно описать одним коротким предложением:

- `Signal` хранит корректный дискретный сигнал;
- `CsvReader` читает записи из потока;
- `Statistics` представляет вычисленный результат;
- `Pipeline` применяет последовательность преобразований.

Если описание содержит много союзов «и», класс, возможно, взял слишком много задач. Например, класс, который одновременно хранит сигнал, разбирает командную строку, читает файл и печатает отчёт, трудно тестировать и изменять.

## 13. Типичные ошибки

### Неинициализированные поля

Числовое поле без начального значения может содержать неопределённое значение. Используй `{}` или явно инициализируй его в конструкторе.

### Публичные поля при наличии инварианта

Если любое присваивание может сделать объект некорректным, поле должно быть закрытым, а изменения — проходить через проверяемые операции.

### Сеттер для каждого поля

Такой интерфейс часто просто маскирует открытые поля. Сначала определи допустимые предметные операции.

### Забытый `const` у метода чтения

Метод нельзя будет вызвать у `const`-объекта или через `const&`, даже если он логически ничего не меняет.

### Присваивание в теле вместо списка инициализации

Поле уже было создано до тела конструктора. Для `const`-полей, ссылок и типов без конструктора по умолчанию такой подход вообще невозможен.

### Параметр скрывает поле

В конструкторе `name = name;` обе записи могут обозначать параметр. Соглашение `name_` для поля или явное `this->name` устраняет неоднозначность.

### Возврат ссылки на временный или локальный объект

Нельзя вернуть `const std::string&` на локальную строку функции. Ссылка останется после уничтожения строки.

### Неконтролируемая ссылка на внутренний контейнер

Возврат `std::vector<double>&` позволяет внешнему коду менять данные в обход правил класса.

### «Божественный объект»

Один класс не должен отвечать за хранение, ввод-вывод, интерфейс пользователя, вычисления и форматирование отчёта одновременно.

### Необоснованное наследование

Повторное использование кода само по себе не доказывает отношение «является». Сначала проверь композицию.

## 14. Упражнения

### Уровень 1. Простые типы данных

1. Создай `struct Point2D` с координатами `x` и `y`. Напиши свободную функцию расстояния от точки до начала координат.
2. Создай `struct MinMax` и функцию, вычисляющую минимум и максимум непустого вектора.
3. Объяви `enum class Direction` со значениями `left`, `right`, `up`, `down`. Напиши функцию, возвращающую русское название направления.
4. Создай `struct Measurement` и отсортируй вектор измерений по времени.

Для расстояния пригодятся `std::sqrt` и сумма квадратов координат. Для преобразования `enum class` используй `switch`. Компаратор сортировки должен сравнивать поле `time` двух записей.

</details>

### Уровень 2. Классы с инвариантами

1. Спроектируй класс `ClosedInterval`, для которого `minimum <= maximum`. Добавь методы `contains`, `length` и `shift`.
2. Спроектируй класс `MatrixShape`, хранящий положительные числа строк и столбцов. Добавь `elementCount` и проверку индекса.
3. Создай класс `Thermostat` с допустимым диапазоном целевой температуры. Вместо свободного сеттера предоставь операцию изменения температуры, сохраняющую инвариант.
4. Создай класс `NamedSeries`, хранящий непустое имя и набор значений. Предоставь доступ к значениям только для чтения.

<details><summary>Подсказка</summary>

Сначала выпиши инвариант каждого класса. Обязательные данные принимай в конструкторе. Если параметры нарушают инвариант, можно выбросить `std::invalid_argument`. Методы наблюдения сделай `const`.

</details>

### Уровень 3. Небольшая предметная модель

1. Создай модель многоканальной записи. `Recording` содержит имя и несколько каналов `Signal`. Реши и документируй, обязаны ли каналы иметь одинаковую частоту дискретизации.
2. Спроектируй `Histogram`: границы интервалов должны идти по возрастанию, а число счётчиков согласовано с числом интервалов. Добавь операцию добавления значения.
3. Создай `ExperimentConfig`, который не позволяет задать нулевое число испытаний, пустое имя или вероятность вне `[0, 1]`. Отдели конфигурацию от результата эксперимента.
4. Возьми класс из своей предыдущей программы и письменно раздели его обязанности. Если обязанностей больше одной, предложи декомпозицию через композицию.

<details><summary>Подсказка</summary>

Не начинай с наследования. Сначала нарисуй объекты и подпиши «содержит». Для проверки нескольких каналов конструктор может сравнить их свойства до сохранения. Результат вычисления часто удобно представить простой структурой, а правила корректности входа — отдельным классом конфигурации.

</details>

## 15. Вопросы для самопроверки

### В чём языковое различие между `struct` и `class`?

Только в доступе и наследовании по умолчанию: у `struct` они публичные, у `class` — закрытые. Практический выбор выражает намерение проектирования.

### Когда открытые поля структуры уместны?

Когда тип является простой записью или результатом, а свободное изменение полей не нарушает сложный инвариант.

### Зачем нужен `enum class`?

Чтобы представить конечный набор именованных вариантов отдельным строгим типом и не смешивать их с произвольными целыми.

### Что такое инвариант?

Условие, которое истинно для каждого корректного объекта после конструктора и после любой публичной операции.

### Почему обязательные данные лучше передать в конструктор?

Так объект сразу создаётся готовым и не проводит часть жизни в неполном или некорректном состоянии.

### Зачем нужен список инициализации?

Он задаёт непосредственное создание полей. Присваивание в теле выполнялось бы уже после их создания.

### Что обещает `const` после метода?

Метод не изменяет наблюдаемое состояние объекта и может быть вызван у `const`-объекта.

### Почему сеттер для каждого поля — не настоящая инкапсуляция?

Он может оставить все варианты некорректного изменения доступными. Полезнее дать предметные операции, сохраняющие правила класса.

### Что выражает композиция?

Отношение «объект содержит другие объекты как свои части».

### Нужно ли всякую функцию делать методом класса?

Нет. Если операция не требует доступа к закрытому состоянию и симметрично работает с данными, свободная функция может быть яснее.

## Чек-лист готовности

Ты готов двигаться дальше, если можешь:

- [ ] создать простой тип-запись через `struct`;
- [ ] заменить числовые коды состояний на `enum class`;
- [ ] обработать все варианты перечисления через `switch`;
- [ ] сформулировать инвариант класса одним-двумя предложениями;
- [ ] написать конструктор со списком инициализации;
- [ ] разделить `public` и `private`;
- [ ] отметить методы чтения как `const`;
- [ ] не добавлять сеттер без предметной необходимости;
- [ ] выбрать композицию для отношения «содержит»;
- [ ] объяснить, почему конкретная операция является методом или свободной функцией;
- [ ] собрать оба примера в режиме C++20 без предупреждений.

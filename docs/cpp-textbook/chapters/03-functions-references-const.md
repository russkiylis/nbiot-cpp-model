# Глава 3. Функции, ссылки и `const`

## Зачем тебе нужна эта тема

Пока программа состоит из двадцати строк, её можно целиком держать в `main`. Но уже на сотне строк такой код трудно проверять, повторно использовать и изменять. Функция позволяет дать имя отдельному действию: «ограничить значение», «проверить диапазон», «перевести единицы», «рассчитать мощность».

В MATLAB ты тоже создавал функции, но в C++ к ним добавляется важный вопрос: **как именно данные попадают в функцию**. Значение можно скопировать, можно дать функции доступ к существующему объекту, а можно разрешить только чтение. От этого зависят понятность интерфейса, безопасность и иногда производительность.

В этой главе ты разберёшь три основных способа передачи параметров:

- по значению — функция получает самостоятельное значение;
- по ссылке — функция работает с исходным объектом и может его изменить;
- по константной ссылке — функция видит исходный объект, но не может его изменить.

Это основа почти любого современного C++ API.

## Результаты обучения

После главы ты сможешь:

- объявить, определить и вызвать функцию;
- сформулировать простой контракт функции;
- выбрать передачу параметра по значению, по ссылке или по `const`-ссылке;
- отличить входной параметр от изменяемого результата;
- применять `const` к переменным и параметрам;
- объяснить область видимости и время жизни локальной переменной;
- безопасно возвращать результат по значению;
- распознать опасную ссылку на уже уничтоженный объект;
- отделять вычисления от ввода и вывода.

## 1. Функция как маленький контракт

Рассмотрим сигнатуру:

```cpp
double celsiusToFahrenheit(double celsius);
```

Она сообщает:

- имя операции — `celsiusToFahrenheit`;
- вход — одно число типа `double`;
- результат — одно число типа `double`;
- исходный аргумент функция изменить не сможет, потому что он передаётся по значению.

Перед реализацией полезно письменно ответить на четыре вопроса:

1. Какие входы допустимы?
2. Что функция возвращает?
3. Может ли она изменить аргументы?
4. Что произойдёт при ошибочном входе?

Это и есть упрощённый контракт. Он важнее конкретного тела функции.

### Объявление и определение

Объявление сообщает компилятору, что функция существует:

```cpp
double celsiusToFahrenheit(double celsius);
```

Определение содержит тело:

```cpp
double celsiusToFahrenheit(double celsius)
{
    return celsius * 9.0 / 5.0 + 32.0;
}
```

В маленьком файле определение часто находится до `main`. В большом проекте объявление обычно помещают в заголовочный файл, а определение — в `.cpp`. Сейчас достаточно понимать различие: объявлений может быть несколько, а обычное определение в программе должно быть одно.

## 2. Передача по значению

Параметр без `&` передаётся по значению:

```cpp
double square(double value)
{
    value *= value;
    return value;
}
```

Изменяется локальный параметр `value`, а не переменная вызывающего кода:

```cpp
double x = 3.0;
double result = square(x);
// x по-прежнему равен 3.0, result равен 9.0
```

Для небольших типов вроде `int`, `double`, `bool` и `char` передача по значению обычно является самым простым и правильным выбором.

У передачи по значению есть полезное свойство: внутри функции можно свободно менять параметр, не затрагивая вызывающий код. Интерфейс получается предсказуемым.

## 3. Возврат результата

Ключевое слово `return` завершает функцию и передаёт значение вызывающему коду:

```cpp
double absoluteValue(double value)
{
    if (value < 0.0) {
        return -value;
    }
    return value;
}
```

Возврат локального объекта **по значению** безопасен. Не нужно опасаться, что локальная переменная исчезнет: значение результата будет корректно передано наружу. Современный компилятор умеет устранять многие промежуточные копирования.

Если функция ничего не возвращает, используется `void`:

```cpp
void printSeparator()
{
    std::cout << "---\n";
}
```

Но вычислительная функция обычно должна возвращать результат, а не печатать его. Тогда её легче тестировать и повторно использовать.

## 4. Ссылка: другое имя существующего объекта

Ссылка обозначается символом `&`:

```cpp
void doubleValue(double& value)
{
    value *= 2.0;
}
```

Здесь `value` — не самостоятельная копия. Это другое имя переменной, переданной при вызове:

```cpp
double amplitude = 1.5;
doubleValue(amplitude);
// amplitude теперь равна 3.0
```

Изменяемую ссылку стоит использовать, когда изменение аргумента является явной частью контракта. По сигнатуре `double&` читатель сразу видит: функция может поменять объект.

### Важные свойства ссылки

- ссылка должна быть связана с объектом при создании;
- обычная ссылка не имеет состояния «ни на что не ссылается»;
- ссылку нельзя позднее «переключить» на другой объект;
- изменение через ссылку изменяет исходный объект;
- ссылка не владеет объектом и не продлевает его жизнь автоматически во всех ситуациях.

Ссылки не нужно использовать для каждого параметра. Для одного `double` передача по значению обычно яснее.

## 5. Константная ссылка

Константная ссылка выглядит так:

```cpp
const std::string& name
```

Она означает: функция получает доступ к существующей строке, но обещает не менять её.

```cpp
void printMeasurement(const std::string& name, double value)
{
    std::cout << name << ": " << value << '\n';
}
```

Так часто передают строки и другие объекты, копирование которых может быть заметнее копирования одного числа.

Полезная начальная эвристика:

| Ситуация | Тип параметра |
|---|---|
| Небольшое число или флаг | `T` |
| Функция должна изменить объект | `T&` |
| Функция только читает крупный объект | `const T&` |

Это не абсолютный закон, но хороший старт.

## 6. Что именно делает `const`

Константную переменную нельзя изменить после инициализации:

```cpp
const double pi{3.141592653589793};
```

Она обязана сразу получить значение. Попытка присвоить ей новое значение вызовет ошибку компиляции.

В параметре `const T&` слово `const` относится к объекту, видимому через ссылку:

```cpp
void show(const std::string& text)
{
    // text += "!"; // ошибка: через эту ссылку менять строку нельзя
    std::cout << text << '\n';
}
```

`const` — не декоративная пометка. Компилятор проверяет обещание функции.

Используй `const`, когда значение не должно меняться. Это помогает и читателю, и компилятору.

## 7. Область видимости и время жизни

Переменная, созданная внутри блока `{ ... }`, видна только в этом блоке и уничтожается при выходе из него:

```cpp
if (temperature < 0.0) {
    const std::string message{"frost"};
    std::cout << message << '\n';
}
// message здесь уже не существует
```

Параметры функции и её локальные переменные живут до завершения вызова.

Поэтому нельзя возвращать ссылку на локальную переменную:

```cpp
const std::string& brokenFunction()
{
    const std::string local{"temporary"};
    return local; // опасно: local уничтожится при выходе из функции
}
```

После завершения функции такая ссылка станет висячей: она обозначает объект, которого уже нет. Использование висячей ссылки приводит к неопределённому поведению.

Правильный вариант — вернуть строку по значению:

```cpp
std::string makeMessage()
{
    return "ready";
}
```

## 8. Несколько результатов

В MATLAB функция может естественно возвращать несколько значений:

```matlab
[minimum, maximum] = bounds(values)
```

В C++ есть несколько вариантов:

- вернуть небольшой объект, содержащий оба результата;
- вернуть `std::pair` или `std::tuple`;
- записать результаты в параметры-ссылки;

Пока мы разберём последний вариант, потому что он хорошо показывает изменяемые ссылки:

```cpp
bool divide(int dividend, int divisor, int& quotient, int& remainder)
{
    if (divisor == 0) {
        return false;
    }

    quotient = dividend / divisor;
    remainder = dividend % divisor;
    return true;
}
```

Возвращаемый `bool` сообщает об успехе, а две ссылки получают результаты. Для большого API отдельный тип результата часто был бы понятнее, но такой интерфейс допустим для небольшой функции, если он хорошо документирован.

## 9. Отличия от MATLAB

### Входные параметры

В MATLAB при обычной работе с числом тебе редко нужно думать, копируется оно или нет. В C++ способ передачи виден прямо в сигнатуре и является частью интерфейса.

### Изменение аргументов

Функция с параметром `T&` может изменить переменную вызывающего кода. Это нужно замечать при чтении программы. Если изменение не нужно, выбирай значение или `const T&`.

### Тип результата

Тип каждого параметра и результата указывается явно. Компилятор проверяет соответствие вызова сигнатуре.

### Несколько результатов

В MATLAB несколько выходов встроены в синтаксис. В C++ обычно создают отдельный тип результата, используют пару/кортеж или, для простого случая, выходные ссылки.

### Время жизни

В C++ особенно важно, чтобы ссылка не пережила объект. Привычного MATLAB workspace, который незаметно удерживает множество значений, здесь нет.

## 10. Разобранный пример 1: чистые численные функции

Программа полностью компилируется как один файл.

```cpp
#include <iostream>

double clamp(double value, double low, double high)
{
    if (value < low) {
        return low;
    }
    if (value > high) {
        return high;
    }
    return value;
}

double linearInterpolation(double left, double right, double fraction)
{
    const double safeFraction{clamp(fraction, 0.0, 1.0)};
    return left + (right - left) * safeFraction;
}

int main()
{
    const double start{10.0};
    const double finish{20.0};

    std::cout << linearInterpolation(start, finish, 0.25) << '\n';
    std::cout << linearInterpolation(start, finish, 1.50) << '\n';
}
```

Разберём решения:

- все числовые параметры небольшие, поэтому передаются по значению;
- `clamp` не печатает результат и не меняет аргументы;
- промежуточное значение `safeFraction` объявлено `const`, потому что после вычисления не меняется;
- вторая функция повторно использует первую;
- значение `1.50` ограничивается единицей, поэтому второй результат равен `20`;
- `main` отвечает за демонстрационный вывод, а вычислительные функции не зависят от консоли.

Пример команды сборки:

```bash
c++ -std=c++20 -Wall -Wextra -Wpedantic example.cpp -o example
```

## 11. Разобранный пример 2: изменяемые и константные ссылки

```cpp
#include <iostream>
#include <string>

bool divide(int dividend, int divisor, int& quotient, int& remainder)
{
    if (divisor == 0) {
        return false;
    }

    quotient = dividend / divisor;
    remainder = dividend % divisor;
    return true;
}

void printDivision(const std::string& label, int dividend, int divisor)
{
    int quotient{0};
    int remainder{0};

    if (!divide(dividend, divisor, quotient, remainder)) {
        std::cout << label << ": division by zero\n";
        return;
    }

    std::cout << label << ": quotient = " << quotient
              << ", remainder = " << remainder << '\n';
}

int main()
{
    const std::string firstLabel{"first calculation"};
    printDivision(firstLabel, 17, 5);
    printDivision("second calculation", 9, 0);
}
```

Что здесь важно:

- `dividend` и `divisor` передаются по значению: функция только читает небольшие числа;
- `quotient` и `remainder` передаются по изменяемой ссылке: успешный вызов записывает в них результаты;
- при делении на ноль функция возвращает `false` и не выдаёт выдуманный результат;
- `label` передаётся по `const std::string&`: функция читает существующую строку;
- строковый литерал тоже можно передать в такой параметр;
- локальные `quotient` и `remainder` живут до окончания `printDivision`, чего достаточно для вызова `divide`.

## 12. Типичные ошибки

### Ошибка 1. Ссылка используется без необходимости

```cpp
double square(const double& value);
```

Для одного `double` ссылка обычно только усложняет интерфейс. Лучше `double square(double value)`.

### Ошибка 2. Неожиданное изменение аргумента

```cpp
void calculate(double& input);
```

Если функция логически должна только вычислить результат, изменение `input` может удивить вызывающий код. Часто яснее вернуть новое значение.

### Ошибка 3. Большой объект передаётся по значению без причины

```cpp
void printText(std::string text);
```

Это создаёт самостоятельную строку. Если функции нужно только чтение, обычно подходит `const std::string&`.

### Ошибка 4. Возврат ссылки на локальный объект

Локальная переменная уничтожится при выходе из функции. Возвращай значение.

### Ошибка 5. Вычислительная функция сама читает и печатает

Функция, которая одновременно спрашивает данные, считает и печатает, плохо тестируется. Передай ей готовые аргументы и верни результат.

### Ошибка 6. `const` добавляется только «для красоты»

Если значение не должно меняться, `const` должен отражать это обещание. Если объект действительно нужно изменять, не пытайся обходить `const` приведениями типов.

### Ошибка 7. Результат при ошибке остаётся двусмысленным

Если деление на ноль возвращает `0`, вызывающий код не отличит ошибку от правильного нулевого результата. Ошибка должна быть представлена явно.

## 13. Упражнения

Сначала запиши контракт каждой функции простыми словами. Затем напиши код и минимум три проверки: обычный случай, граничный случай и ещё один отличающийся случай.

### Уровень 1. Небольшие функции по значению

1. Напиши `double cube(double value)`.
2. Напиши `bool isInside(double value, double low, double high)`. Границы считаются включёнными.
3. Напиши `double power(double base, unsigned int exponent)` без библиотечной функции возведения в степень.
4. Реши, что должна делать `isInside`, если `low > high`, и зафиксируй это в контракте.

<details>
<summary>Подсказка к уровню 1</summary>

Для `power` начни с результата `1.0` и умножай его на `base` ровно `exponent` раз. Не забудь случай нулевой степени. Для неверного диапазона можно либо считать вход ошибочным, либо сначала упорядочить границы — важно выбрать и документировать один вариант.

</details>

### Уровень 2. Осознанные ссылки

1. Напиши `void sortTwo(double& first, double& second)`, после которой `first <= second`.
2. Напиши `bool reciprocal(double input, double& result)`, возвращающую `false` для нуля.
3. Напиши `void addPrefix(const std::string& prefix, std::string& text)`.
4. Для каждого параметра объясни, почему это значение, изменяемая ссылка или константная ссылка.

<details>
<summary>Подсказка к уровню 2</summary>

В `sortTwo` достаточно обменять значения только тогда, когда первое больше второго. Для обмена можно временно сохранить одно значение. В `reciprocal` не изменяй `result`, если операция невозможна: так контракт будет проще проверять.

</details>

### Уровень 3. Маленькая библиотека пересчёта

Сделай программу для обработки измерения датчика.

Требования:

- функция переводит сырое значение по линейной формуле `scaled = raw * gain + offset`;
- отдельная функция ограничивает результат допустимым диапазоном;
- отдельная функция определяет, попало ли значение в аварийный диапазон;
- отдельная функция печатает строку отчёта и принимает название датчика по `const`-ссылке;
- вычислительные функции ничего не читают из `std::cin` и ничего не печатают;
- проверь как минимум нормальное значение, значение ниже минимума и значение выше максимума.

<details>
<summary>Подсказка к уровню 3</summary>

Сначала выпиши сигнатуры четырёх функций. Для числовых входов подойдут значения. Название датчика удобно передать как `const std::string&`. В `main` последовательно вызови масштабирование, ограничение, проверку и только затем вывод.

</details>

## 14. Вопросы для самопроверки

### 1. Чем объявление функции отличается от определения?

Объявление сообщает имя, параметры и тип результата. Определение дополнительно содержит тело функции.

### 2. Изменится ли исходная переменная при передаче параметра по значению?

Нет. Функция работает со своим значением параметра.

### 3. Что означает параметр `double& value`?

Функция получает ссылку на существующий `double` и может изменить исходный объект.

### 4. Что означает `const std::string& text`?

Функция читает существующую строку через ссылку и не может изменить её через эту ссылку.

### 5. Почему небольшой `int` обычно передают по значению?

Это просто, ясно и не создаёт значимой стоимости копирования.

### 6. Можно ли безопасно вернуть локальный `std::string` по значению?

Да. Значение будет корректно передано вызывающему коду.

### 7. Можно ли вернуть ссылку на обычную локальную переменную?

Нет. После выхода из функции объект уничтожится, и ссылка станет висячей.

### 8. Зачем отделять вычисление от печати?

Чистую вычислительную функцию легче тестировать, повторно использовать и вызывать из другого интерфейса.

### 9. Всегда ли `const&` лучше передачи по значению?

Нет. Для небольших числовых типов значение обычно проще. Выбор зависит от размера объекта и требуемой семантики.

### 10. Что должно быть ясно из контракта функции?

Допустимые входы, результат, возможное изменение аргументов и поведение при ошибке.

- [ ] Я умею объявлять, определять и вызывать функции.
- [ ] Перед написанием функции я могу сформулировать её входы, результат и ошибочные случаи.
- [ ] Я понимаю передачу по значению.
- [ ] Я понимаю, что изменяемая ссылка может поменять исходный объект.
- [ ] Я умею использовать `const T&` для чтения существующего объекта.
- [ ] Я не передаю один `double` по ссылке без причины.
- [ ] Я понимаю область видимости локальной переменной.
- [ ] Я не возвращаю ссылку на локальный объект.
- [ ] Я безопасно возвращаю результат по значению.
- [ ] Мои вычислительные функции не зависят от консольного ввода-вывода.
- [ ] Я могу объяснить выбор способа передачи каждого параметра в своём решении.
- [ ] Я проверил упражнения обычными и граничными входами.
